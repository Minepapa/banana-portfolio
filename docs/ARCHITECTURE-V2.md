> **상태**: 설계 전용 모드(`CLAUDE.md` 참조) — 이 문서는 브레인스토밍으로 합의된 내용을
> 세션이 끊겨도 유실되지 않게 기록하는 용도다. "이제 구현해보자"라는 명시적 지시 전까지는
> 이 문서를 갱신하는 것만 하고 실제 코드는 건드리지 않는다.
>
> v1이 왜 이렇게 생겼는지는 `docs/V1-ARCHIVE.md` 참고. v2는 v1의 구조를 답습하지 않고
> 처음부터 다시 설계한다 — 지금까지 나온 방향은 v1과 상당히 다르다(구글시트→Obsidian,
> 대시보드+텔레그램 역할분리, 추세추종 결합 등).
>
> 확정 용어의 정의는 `/CONTEXT.md`(글로서리), 되돌리기 어려운 주요 결정의 배경은
> `docs/adr/`(아키텍처 결정 기록) 참고.

## 왜 다시 설계하나

v1은 "포트폴리오 시각화"에서 출발해 기능을 하나씩 덧붙여온 앱이라 사용성이 정리되지 않았다.
v2는 **처음부터 "이 앱을 어떻게 쓸 것인가"**를 먼저 정하고 그 사용 패턴에 맞춰 구조를 잡는다.

## 핵심 방향 4가지

1. 구글 스프레드시트 → **Obsidian Vault**로 기록 이전. 모든 수치·근거·이력을 날짜와 함께
   빠짐없이 구조화해서 남긴다 (앱에 안 보이는 것도 Vault엔 있어야 한다는 원칙).
2. **대시보드(앱)는 숫자만.** 질문·판단·주문승인은 **텔레그램**으로.
3. 자산 숫자 표시를 넘어, **펀더멘털 점검 + 기술적 판단**을 결합해 매수/매도까지 제안하고
   텔레그램 승인을 거쳐 자동 체결한다(⚠️ KIS로 이관된 퀀트 트랙 계좌만 해당 — 자산분배
   트랙은 승인 후에도 오너가 직접 체결한다, "트랙별 구성 분리" 절 참고).
   > 당초 "펀더멘털 + **추세추종**"이었으나 2026-07-29 문헌 리서치 결과 **추세추종은
   > 채택하지 않기로 변경**(한국 개별주식에서 모멘텀이 작동하지 않는다는 증거) —
   > "펀더멘털·기술적 알고리즘" 절 참고.
4. 불필요한 기능은 과감히 제거. 평가·매수·매도는 명확한 알고리즘 근거가 있어야 한다.
   근거 없는 임계값은 배제한다(`profile/kpi_baseline.md` §8 방법론 계승 — 실증 데이터 +
   문헌 대조로 검증한 값만 사용).

## ⭐ 2트랙 구조 — 이 시스템의 최상위 골격 (2026-07-31 확정)

> **가장 중요한 구조적 사실.** 이 문서의 다른 모든 설계는 "이 내용이 어느 트랙에
> 속하는가"를 먼저 확인한 뒤 읽어야 한다. 두 트랙은 성격이 정반대이고, **섞이면 안 된다.**

```
전체 자산
├─ 80%  【자산분배 트랙】 안정
│   ├─ ETF 중심 (지수추종 + 섹터별)
│   ├─ 목표 비중 대비 리밸런싱
│   ├─ 현재 위탁계좌 개별종목 = 전환 대상 (수익 실현 후 ETF로)
│   └─ ❌ 개별종목 신규 매수 없음 (확정)
│
└─ 20%  【퀀트 매매 트랙】 공격
    ├─ 별도 계좌(한국투자증권) — 계좌 수준에서 철저히 분리
    ├─ 자동 매수/매도 + 텔레그램 승인
    └─ 방법론 백지 상태 — 이론 기반으로 처음부터 구축
```

**핵심 제약**: 두 개념이 섞이지 않도록 **계좌를 철저히 분리**한다. 안정적 자산배분과
퀀트 매매는 목적·기간·위험 성격이 전혀 다르므로, 한 화면·한 장부에서 뭉뚱그리면 판단이
오염된다.

**80/20 비율도 리밸런싱 대상(확정)**: 퀀트 트랙에서 수익이 나면 그 비중이 목표(20%)를
넘게 된다. 초과분은 자산분배 트랙으로 이전한다 — **퀀트가 잘될수록 위험 노출이 저절로
커지는 것을 막기 위함**이다.

### 트랙별로 필요한 것

| | 자산분배 트랙 (80%) | 퀀트 트랙 (20%) |
|---|---|---|
| 필요한 설계 | 리밸런싱 규칙 · ETF 선택 기준 · **개별종목→ETF 전환 계획** | **전부 신규**(백지) |
| 개별종목 신규 매수 | ❌ 없음 | ✅ 퀀트 방식으로 |
| 담당 부서 | Athena | **Kairos**(아래 참고) |

### 부서 재배치 (확정)

**Kairos = 퀀트 트랙 전담.** Kairos는 원래 추세추종 신호 전담으로 신설했으나 추세추종이
증거 부족으로 기각되면서 **역할이 비어 있던 상태**였다. 퀀트 트랙이 그 자리에 정확히
들어맞는다. Athena는 자산분배 트랙(리밸런싱·ETF 전환)을 담당한다. 트랙이 부서 단위로
분리돼 섞일 위험이 구조적으로 줄어든다.

### ⚠️ 이 변경이 기존 설계에 미치는 영향

**그대로 유효(트랙 무관)**: Vault 4대 분류 · 텔레그램 승인 흐름 · 결정론적 검문소 ·
섀도우모드 · 백업·장애감지 · Firestore 미러 · v1→v2 마이그레이션.
→ 특히 **검문소와 섀도우모드는 퀀트 트랙에서 오히려 더 중요**해진다(자동매매 본격화).

**역할이 바뀌거나 재배치가 필요한 것**:

| 항목 | 원래 목적 | 새 구조에서 |
|---|---|---|
| **MSCI Quality 매수 게이트** (2026-07-31 설계 완료) | 개별종목 신규 매수 자격 판단 | ⚠️ **자산분배 트랙에서 개별종목을 더 안 사므로 원래 용도 소멸.** 퀀트 트랙의 팩터로 전용할지 폐기할지 미정 |
| **F-Score 매도 뼈대** | 펀더멘털 훼손 시 매도 | 🔄 목적 변경 — "언제 수익 실현하고 ETF로 갈아탈까"(전환 판단)로 |
| 급락 감지·PEAD·시장대비 등 타이밍 로직 | 개별종목 매수 타이밍 | ⚠️ 자산분배 트랙에선 불필요. 퀀트 트랙에서 재검토 대상 |

## 시스템 구성

| 구성요소 | 역할 |
|---|---|
| **Obsidian Vault** (로컬) | 유일한 기록 원본(source of truth). 4대 그룹(Facts/State/Decisions/Knowledge)으로 분류 |
| **로컬 자동화** (Node, 지금 launchd 잡의 계승) | 카카오 알림 파싱 → Vault 직접 기록, 가격 폴링, 펀더멘털+추세추종 계산, Firestore 미러 갱신, 매수/매도 제안 생성 |
| **Firestore** (클라우드) | 대시보드 전용 **파생 요약 미러** — 원본이 아니라 캐시. 언제든 Vault에서 재생성 가능 |
| **대시보드 앱** (정적, GitHub Pages 유지) | 구글 로그인으로 Firestore 미러만 읽어 숫자 표시. 서술·판단 없음 |
| **텔레그램 봇** | 질문응답 + 상세 사유 포함 매수/매도 제안 + 텍스트 답장 승인, 단일 알림 채널 |
| **브로커 API** (KIS 등, v1에서 이관) | 승인된 제안의 자동 체결 실행 — **퀀트 트랙(KIS)만 해당**, 자산분배 트랙(NH·삼성증권)은 미체결 리마인드까지만(아래 "트랙별 구성 분리" 절 참고) |

### 데이터 흐름

```
카카오 알림(체결·배당·현금이벤트) / 스케줄(분기·월간) / 거시신호(1일1회) / 사용자 질의
        │
        ▼
   로컬 자동화 (Node)
        │
        ├─▶ Obsidian Vault (원본 기록 — Facts/State/Decisions/Knowledge)
        │
        ├─▶ Firestore 미러 (탭당 문서 1개, 매번 통째로 재생성)
        │         │
        │         ▼
        │    대시보드 앱 (구글 로그인 → 숫자만 표시)
        │
        └─▶ 텔레그램 (제안 상세사유 + 텍스트 승인/거부)
                  │
                  ▼ (승인 시, 결정론적 검문소 통과 후 — "안전장치 계층" 절 참고)
             브로커 API 자동 체결 ─▶ Vault Facts/Ledger에 체결 기록
```

## 판단 원칙 (기존 판테온 조직 원칙 유지)

- 펀더멘털(자격 판단)·추세추종(타이밍 계산)의 **수치 산출은 기계적**이어도 된다
  (v1의 "Node가 결정론 계산, LLM은 해석만"과 동일 철학).
- 그러나 **"그래서 지금 사라/팔아라"라는 최종 결론은 반드시 LLM 종합**
  (투자전략실 Athena + 리스크관리실 Themis)이 내린다. 지표 하나가 임계값을 넘었다고
  기계적으로 주문이 나가지 않는다. (기존 원칙: 판단에 하드코딩 금지, 결정은 부서 의견의
  복합 종합이지 트리거 기계 적용이 아님.)

## 실행 흐름 (주문)

1. 스케줄(자산분배 분기·퀀트 월간)·거시신호·신규현금 이벤트·사용자 텔레그램 질의 중
   하나로 투자실행협의체 트리거("트리거 주기" 절 참고 — 인트라데이 가격 폴링은 없다).
2. **트랙별로 다른 경로를 탄다**(⭐ 2트랙 구조 확정 이후 — "판테온 조직 재설계" 절의
   투자실행협의체 표 참고): 자산분배 트랙은 Hermes→**Athena**(종합·전술조정안)→Themis
   →Zeus, 퀀트 트랙은 Hermes→**Kairos**(팩터신호 계산·종합)→Themis→Zeus. 둘 중 한
   부서만 참여하고 다른 하나는 그 안건에 관여하지 않는다.
3. Zeus가 승인하면 **텔레그램에 상세 사유와 함께 제안 발송**(텍스트 답장으로 승인/거부 —
   인라인 버튼 불가, "텔레그램 상시 응답 기술 메커니즘" 절 참고).
4. Frank의 "승인" 답장 확인 → **결정론적 검문소**(가격이탈·보유정합성·중복방지 등,
   "안전장치 계층" 절 참고) 통과 → 브로커 API(KIS 등)로 자동 체결. 검문소를 하나라도
   통과 못하면 승인이 있어도 체결되지 않고 Frank에게 재확인 요청.
5. 체결 결과는 Vault의 Facts/Ledger에 기록되고, Decisions/Proposals의 해당 제안 상태가
   갱신되며, Firestore 미러(체결내역 탭)도 갱신된다.

### 체결 기록 권위 소스 (확정 — critic 리뷰 TIER 1 대응)

브로커 API 실행경로와 카카오 알림 파싱경로가 같은 체결을 각자 기록하려 드는 문제는,
이미 설계된 **멱등 dedup 키**(날짜|구분|종목명|수량, v1에서 이식 — "카카오 알림 →
Vault 파싱 파이프라인" 절 참고) 자체가 해결한다. 두 경로 중 어느 쪽이든 먼저 그 키로
Facts/Ledger에 쓰면, 뒤이어 같은 키로 도착하는 다른 경로는 "이미 기록됨"으로 인식해
새 항목을 만들지 않는다 — 새 메커니즘이 아니라 기존 멱등성 설계의 자연스러운 결과다.

- **KIS로 이관된 계좌(투자실행협의체를 거친 거래)**: 브로커 API 체결 응답이 1차
  기록(텍스트 파싱보다 구조화돼 있고 신뢰도 높음). 뒤이어 도착하는 같은 거래의 카카오
  알림은 **대조 확인용**으로만 쓰인다 — 값이 일치하면 조용히 스킵, 수량·가격 등이
  불일치하면(부분체결 포함) Hermes가 정합성 경고를 남긴다.
- **아직 미이관 계좌(NH·삼성증권, 수동 거래)**: Frank가 증권사 앱에서 직접 체결한
  것이라 투자실행협의체를 거치지 않는다 — 카카오 알림이 유일한 소스이므로 지금처럼
  그대로 권위 있는 기록.

**Position Journal 오프닝 규칙 보강**: "포지션 하나당 파일 하나" 원칙만으로는 Proposal이
없는 수동 거래(NH·삼성)의 포지션 시작을 못 잡는다. → 카카오 파싱이 **기존 열린 포지션과
매칭되지 않는 신규 매수**를 감지하면, Proposal 연결 없이 "수동 진입"으로 표시된 새
Position Journal 파일을 자동 생성한다.

**부분체결 처리(확정, 2026-08-04)**: 승인은 100주인데 30주만 체결된 경우, **별도 자동
보정 메커니즘이 필요 없다** — 위 체결 기록 권위 소스 규칙 자체가 이미 실제 체결량(30주)을
State에 정확히 반영하므로, State는 항상 "진짜 보유량" 그대로다. 목표 대비 여전히 남은
갭(미체결 70주만큼)은 **다음 정기 점검(자산분배 분기·퀀트 월간)이 그 시점의 실제 잔고
기준으로 다시 계산하면서 자연스럽게 다시 잡힌다** — 두 트랙 모두 "그때그때 실제 잔고
기준 재계산" 구조라 이미 자기 보정적이다. 필요한 건 새 로직이 아니라 **추적성**뿐 —
Proposal 상태를 "부분체결(30/100)"로 명시해 왜 갭이 남았는지 나중에 되짚을 수 있게
한다.

거부 시에도 Decisions/Proposals에 사유와 함께 기록 남김(왜 거부했는지 나중에 되짚기 위함).

## 안전장치 계층 (확정 — critic 리뷰 TIER 1 대응)

**원칙**: 지금 프로젝트에 이미 있는 철학("Node가 결정론적으로 계산·집행, LLM은 해석·판단
만")을 주문 실행에도 그대로 적용한다. Athena·Themis·Zeus가 다 승인하고 Frank가 "승인"
이라고 답장해도, **브로커 API 호출 직전에 LLM 판단과 무관한 결정론적 검문소(Node)를
반드시 통과**해야 실제 체결이 나간다 — 어떤 부서·오너 승인도 이 검문소를 우회하지 못한다.

### 검문소 항목 (전부 통과해야 실행)

| 항목 | 막는 상황 |
|---|---|
| **가격 이탈 체크** | 체결 직전 재조회한 현재가가 제안 생성가 대비 **±1%**를 벗어남 → 실행 거부, **투자실행협의체 전체 재소집**(Hermes→Kairos→Athena→Themis 처음부터 재분석 — 단순 가격 재확인이 아니라 논리 자체가 바뀌었을 수 있어서 전체 재검토, 2026-07-28 확정) |
| **보유현황 정합성** | 매도인데 보유수량 초과, 매수인데 예수금 부족 |
| **중복실행 방지 (Idempotency)** | 이 제안(Proposal ID)이 이미 체결 처리된 걸 재시도/재승인 시도 |
| **제안-승인 일치성** | `reply_to` 없이 애매하게 "승인"만 옴 → **추정하지 않고 재확인 요청**(ADR 0003의 폴백 금지 원칙과 직결) |
| **시장개장 상태** | 장마감·공휴일에 승인 도착 → 즉시체결 대신 다음 개장까지 보류 |
| **단일 활성 제안 원칙** | 같은 종목/자산군+방향에 대해 "대기 중" 제안은 항상 최대 1개 — 같은 트리거(예: 신규 현금 배분)가 다시 발동해도 새 제안을 옆에 쌓지 않고, 기존 대기 제안을 최신 정보로 **교체(supersede)**한다. 이게 없으면 Frank가 한동안 답장을 안 했을 때 여러 제안이 쌓여 "어느 조건으로 체결되는지" 모호해지는 문제가 생긴다. |
| **거부 재상정 쿨다운** | Frank가 거부한 제안은, 그 판단 근거가 됐던 조건(가격·펀더멘털·팩터신호 등)이 **의미있게 바뀌기 전까지 같은 종목/자산군+방향으로 재상정 금지**(2026-07-28 확정) — 조건 불변인데 트리거마다 같은 제안이 또 오면 피로도만 쌓임 |

### 주문 타입: 지정가(limit order) 기본

시장가(즉시체결) 대신 **지정가를 기본**으로 한다 — 제안 근거가 된 가격 근처로 지정가를
걸어, 그 가격을 벗어나면 브로커 단에서부터 아예 미체결로 남는다. 가격이탈 체크(Node)와
이중으로 방어막을 형성한다(체크 하나가 뚫려도 다른 하나가 남음).

### 의도적으로 두지 않는 것: 일일 거래 건수 상한

버그로 인한 난사 주문을 막는 서킷브레이커로 "하루 N건 상한"을 검토했으나, 이 시스템은
500만원 분할매수·장기보유 원칙상 거래 빈도 자체가 원래 낮아 불필요하다고 판단해 **의도적
으로 두지 않는다**(critic 지적에 대한 명시적 결정 — 채택 안 함이지 누락 아님).

### 킬스위치

Frank가 텔레그램에 **"정지"/"STOP"** 명령어를 보내면 즉시 모든 자동 실행이 멈춘다(새
제안 생성은 계속되되, 승인이 와도 체결은 안 나감). 해제는 명시적 명령어로만 — 자동
재개 없음.

### 제안모드 (2026-08-29 신설)

킬스위치가 "이미 승인된 제안의 체결"을 막는 것과 달리, 이 스위치는 **제안이 생성·
발송되는 것 자체**를 막는다. Frank가 텔레그램에 **"제안금지"**를 보내면 new-cash-
allocation·rebalance-proposal·퀀트 제안(create-quant-proposal·watch-price-and-
propose) 전부 새 제안을 만들지 않는다(`createAndSendProposal`의 `proposalsBlocked`
게이트, `scripts/lib/proposal-mode.mjs`) — 기존 대기/승인 제안의 승인·거부 처리는
이 모드와 무관하게 계속된다. 해제는 **"제안요청"** 명령어로만.

**신설 배경**: 자산분배 트랙 자동 제안이 종목 선정 기준 없이 쌓여 승인 대기가 18건까지
늘어났고, 그중 일부는 보유가 없는 자산군(예: 달러)에서 Athena가 매번 다른 브랜드의
ETF를 새로 지어내 사실상 같은 안건이 다른 이름으로 중복 쌓이는 문제가 확인됐다(2026-
08-29, `Log/Implementation/2026-08-29-제안모드+제안중복방지.md` 참고). 오너가 배당주·
리츠·개별 국내외 종목 레거시 정리를 수동으로 진행하는 동안 새 자동 제안이 계속 쌓이지
않도록 이 스위치를 신설했고, 18건은 전부 일괄 거부 처리했다. 재발 방지를 위해
new-cash-allocation·rebalance-proposal 프롬프트에도 "보유 종목 우선 재사용", "신규
종목은 보수율·유동성·추적오차 기준으로 판단하고 이후에도 일관되게 유지" 지시를
추가했다.

### 섀도우모드 (확정 — critic 리뷰 TIER 1 대응, 실거래 전 검증 전략)

**정의**: 파이프라인 전체(가격폴링→신호생성→투자실행협의체→Zeus 승인→텔레그램 제안·
Frank 승인/거부)는 실전과 동일하게 돌아가되, **마지막 브로커 API 호출만 실제 발주
대신 로그로 대체**한다("SHADOW: 실제였다면 삼성전자 10주 매수 체결"). Proposal 상태는
"섀도우체결"로 남아 Decisions/Proposals에 기록되고, Facts/Ledger에는 실제 체결로
기록하지 않는다(가짜 체결이 실제 장부에 섞이면 안 되므로).

- **기본값**: KIS 자동체결 경로는 **처음 배포 시 섀도우모드로 시작**한다.
- **승인도 그대로 수동**: 섀도우모드라고 Zeus 승인만으로 자동 진행하지 않는다 — Frank가
  실전과 똑같이 매번 "승인"/"거부"를 답장해야 한다(2026-07-28 확정). 목적은 알고리즘
  판단력뿐 아니라 `reply_to` 매칭·검문소 등 **파이프라인 전체의 기계적 정확성까지
  실전 투입 전에 검증**하는 것이라, 이 부분을 생략하면 정작 승인 흐름 자체의 버그는
  실제 돈이 걸리기 전까지 발견되지 않는다.
- **실전 전환**: 최소 기간 강제 없음 — Frank가 준비됐다고 판단되면 언제든 텔레그램에
  **"실전전환"** 같은 명시적 명령어를 보내야 전환된다(자동 전환 없음, 킬스위치와 같은
  패턴: 상태 변경은 항상 사람의 명시적 명령으로만).
- 전환 후에도 되돌릴 수 있음(다시 "섀도우전환" 명령으로 복귀) — 일방향 전환이 아니다.

## 신뢰경계 — 외부 콘텐츠 격리 원칙 (확정 — critic 리뷰 TIER 1 대응)

**문제 범위를 먼저 정확히 좁힌다.** "외부 텍스트를 읽는 세션과 주문실행 권한을 가진
세션이 같다"는 critic 지적을 점검한 결과, 실제 위험은 처음 우려보다 훨씬 좁다:

- **카카오 알림 파싱**: 순수 정규식 파서(v1 `parse-notifications.mjs` 그대로 이식) — LLM이
  전혀 개입하지 않는다. 알림 본문에 무엇이 들어있어도 AI가 "읽고 설득당할" 경로 자체가
  없다. 프롬프트 인젝션 벡터 아님.
- **자유 저널링**: Frank 본인이 쓰는 글이라 제3자가 주입할 경로가 아니다.
- **주문 승인 위조 불가**: "안전장치 계층"의 제안-승인 일치성 검문소 덕분에, 실행 여부는
  LLM이 대화 맥락에서 "지금 뭘 믿는가"가 아니라 **Frank의 실제 텔레그램 계정(chat_id
  인증)에서, 정확히 그 제안 ID를 `reply_to`로 지목한 새 메시지가 왔는가**라는 엄격한
  구조적 매칭으로 판정된다. 기사 본문에 승인 지시문이 있어도 Frank 명의의 새 메시지가
  아니므로 이 매칭을 통과할 수 없다.

**진짜 남는 좁은 위험**: Frank가 공유하는 **뉴스·기사 링크**뿐이다. Apollo가 그 내용을
요약해 맥락으로 저장하고 Athena에 참고자료로 넘길 수 있는데, 기사 안에 악의적인 지침성
문구가 숨어 있으면 실행을 직접 탈취하진 못해도 Athena·Zeus의 "판단"에 은근히 스며들
가능성은 있다(사회공학적 위험).

**대응(가벼운 방어로 충분 — 오너 확인)**: 물리적으로 승인판정 경로와 대화·종합 경로를
분리하는 무거운 방어는 채택하지 않는다. 대신:
- Apollo가 링크를 요약할 때 **"외부자료=데이터, 지침 아님"** 원칙을 정생적으로 지킨다
  (구현 단계에서 Apollo 에이전트 정의에 명시할 규칙 — 가져온 텍스트를 지시문처럼 따르지
  않고 순수 요약 대상으로만 취급).
- 이미 있는 2중 방어가 이 원칙을 뒷받침한다: ①Themis의 독립 리스크 검증(Athena 판단에
  대한 회의적 재검토가 원래 역할) ②Frank의 물리적 최종 승인(구조적으로 위조 불가한
  reply_to 매칭). 기사 하나가 Athena **와** Themis를 동시에 속이고, 그걸 Frank가 못
  알아채고 승인까지 해야 실제 피해로 이어진다 — 단일 지점 실패가 아니다.

## 백업·장애감지·Mac 가용성 (확정 — critic 리뷰 TIER 1 대응)

### Mac 단일장애점 — 수용하되 정직하게

이 자동화가 도는 Mac은 집 데스크톱/미니로 **거의 항상 켜져있는** 사용 패턴(오너 확인) —
그래서 별도 호스트를 새로 두지는 않는다. 다만 "거의 항상"이지 "항상"은 아니므로(재부팅·
업데이트·정전), 시스템이 다운됐을 때 **조용히 숨기지 않고 정직하게 티가 나게** 만드는
쪽으로 대응한다(아래 장애감지·대시보드 신선도 배너).

### 백업 — 매일 밤 비공개 git 스냅샷

Google Drive 동기화는 복제일 뿐 백업이 아니다(삭제·손상이 그대로 전파됨). 별도로 **매일
밤 Vault 폴더를 비공개 git 리포지토리에 커밋**한다 — 이 git 리포는 퍼블릭인
banana-portfolio-v2와 무관한 별도 저장소이며, git 자체가 버전별 diff·복구 지점을
무료로 제공한다. Drive 동기화 경로와 완전히 독립적이라, Drive 쪽에서 무슨 사고가 나도
전날 밤 스냅샷으로 복구 가능하다.

### 장애감지 — 독립 워처 + 하트비트

v1의 `record-heartbeat.mjs` 패턴을 계승한다:
- 카카오파싱·가격폴링 같은 핵심 헤드리스 잡은 성공 실행마다 타임스탬프를 하트비트로
  남긴다. **기대 주기(매시간)의 2배(2시간)** 이상 조용하면 이상 신호로 간주.
- 상시 텔레그램 세션(`--channels`)은 **프로세스 생존 여부 자체**를 별도 워처가 확인한다
  (앱 레벨 하트비트가 아니라 프로세스 존재 체크 — 더 단순하고 확실함).
- 이 워처는 **상시 세션과 무관하게 독립적으로 동작하는 별도의 작은 launchd 잡**이다(예:
  30분마다 실행). 상시 세션이 죽어있어도 워처는 살아있어야 알림이 가능하므로, 워처
  자신은 텔레그램 `reply` 도구를 직접 호출해 알림을 보낸다(앞서 확인했듯 `reply`는
  `--channels` 세션과 무관하게 동작 가능).
- 이상 감지 시 텔레그램으로 즉시 알림: "⚠️ Zeus 세션이 응답하지 않습니다" /
  "⚠️ 카카오 파싱이 2시간째 조용합니다."

### 대시보드 신선도 배너

Firestore 미러 스키마에 이미 있는 `updatedAt` 필드를 활용 — 장중 기준 기대 갱신주기보다
오래됐으면(예: 2시간 초과) 대시보드 상단에 "⚠️ 데이터가 오래됐습니다" 배너를 띄운다.
새 필드 추가 없이 이미 설계된 스키마로 구현 가능.

### 남는 잔여 위험(수용)

Mac이 하필 카카오 알림 회전 삭제 시점에 다운돼 있으면 그 알림은 영구 유실될 수 있다 —
"거의 항상 켜져있음" 패턴을 전제로 이 잔여 위험은 수용하고, 대신 위 하트비트로 다운
상태 자체는 빠르게 알아챌 수 있게 한다(유실 방지가 아니라 조기 발견).

## 동시성·시크릿 보관 (확정 — critic 리뷰 TIER 2 대응)

### Vault State 파일 동시쓰기

가격폴링·카카오파싱·투자실행협의체 체결반영 등 여러 잡이 거의 동시에 같은 State 파일
(예: 보유종목 현재수량)을 갱신하려 들 수 있다. Drive 동기화 충돌(구현 메모에 이미 기록)
과는 별개로, **로컬에서부터** 두 프로세스가 동시에 읽고-고치고-쓰면 한쪽 갱신이 유실될
수 있다.

- **락파일**: State 파일을 쓰기 전 `.lock` 파일을 원자적으로 생성해 다른 프로세스의
  동시 쓰기를 막는다. 락 획득 실패 시 짧게 재시도 후 포기(무한 대기 금지).
- **원자적 교체**: 실제 쓰기는 임시 파일에 먼저 쓴 뒤 rename — 쓰는 도중 다른 프로세스가
  읽어 절반만 쓰인 파일을 보는 사고를 방지.
- 이 두 규칙은 각 잡이 따로 구현하지 않고 **공용 유틸리티 모듈**(가칭 `state-writer.mjs`)
  하나로 통일해, 잡마다 락 처리를 다르게 짜서 생기는 사각을 없앤다.

### 시크릿 보관 위치

KIS 브로커 API 키·Firestore 관리자 자격증명은 **Vault·Google Drive 동기화 폴더·git
리포지토리 어디에도 들어가지 않는다** — v1이 이미 쓰던 패턴(로컬 전용 설정 디렉토리,
예: `~/.config/banana-portfolio/`, 구글 OAuth는 macOS Keychain)을 그대로 계승한다.
Vault가 폰과 동기화되는 이상, 그 폴더에 시크릿이 섞이면 개인 기기 밖으로 복제되는
문제로 직결되므로 이 경계는 특히 엄격하게 지킨다.

## Obsidian Vault — 4대 분류

기존 `profile/playbooks/learning/skills` 폴더명에 얽매이지 않고, "이 정보가 어떤 종류의
지식인가"로 새로 분류한다. 기존 이력은 참고만 하고 이 체계로 새로 정리하는 것이 출발점이다.

| 그룹 | 성격 | 예시 내용 |
|---|---|---|
| **1. Facts** | 일어난 일, 불변, 추가만 됨 | 체결·배당·현금흐름 원장 / 가격폴링·추세신호 원자료(롤링 90일 보관 후 폐기) |
| **2. State** | 지금 상태, 매번 덮어쓰기 | 보유종목 현재수량·평균단가, 자산분배 비율, 계좌잔고, 펀더멘털 기준선 |
| **3. Decisions** | 판단 과정과 근거 | 종목평가 카드, 매수/매도 제안+승인상태(Proposals), 포지션저널(매수전 근거→감시→반성) |
| **4. Knowledge** | 천천히 변하는 축적 지식 | 투자성향 관찰 이력(Profile), 전략 원칙(Playbook — 펀더멘털 기준·추세추종 규칙·매수매도 원칙), 회고·교훈, 주간/월간 리포트 |

### 파일 단위 규칙

- **Facts/Ledger**(체결·배당·현금흐름): 이벤트 하나당 파일 하나. 프론트매터(YAML)로
  구조화해 Dataview로 조회하면 지금 시트 탭처럼 테이블로 볼 수 있음.
  **하위폴더로 이벤트 종류를 나눈다(확정, 2026-08-04, 오너 요청)** — `Executions/`
  (체결, **금현물도 여기 합류** — v1이 금현물을 별도 원장으로 뒀다가 버그가 나서
  체결내역에 통합한 전례를 반영해 같은 실수를 반복하지 않는다) · `Dividends/`(배당·
  분배금·채권원리금) · `FundPurchases/`(펀드 적립매수, 좌수 회계가 체결과 달라 별도) ·
  `CashEvents/`(NH 입금·출금 안내 원문 — 이 이벤트로 계좌 잔고를 재계산하는 건 State의
  일이라 여기는 원문 사실만) · `Exchanges/`(환전). **계좌별 폴더는 만들지 않는다** —
  계좌 귀속은 State/Holdings 설계(퀀트·자산분배 트랙 로직 절) 전까지 확정 안 되는
  값이라, 폴더가 아니라 각 파일 frontmatter의 `account` 필드로 나중에 채우고 Dataview로
  재조회한다(이벤트 로그는 쓴 뒤 옮기지 않는다는 원칙과 정합).
- ~~**Facts/MarketPolls**(가격폴링·추세신호 원자료): **롤링 보관(예: 90일) 후 자동
  폐기**. 의미 있는 신호(제안으로 이어진 것)만 Decisions에 영구 기록되므로 손실 없음.~~
  → **2026-08-17 폴더 자체 삭제** — "정리된 항목과 그 이유" 표 참고(전제였던 추세추종
  폴링이 ADR-0012 추신에서 이미 기각됨, 코드로 한 번도 안 만들어짐).
- **Decisions/PositionJournal**: **포지션(종목) 하나당 파일 하나**, 매수 시작부터 완전
  매도까지 시간순으로 누적 기록. 한 파일에서 "이 포지션이 왜 시작되고 어떻게 가고 왜
  끝났는지"를 한눈에 볼 수 있게 함.
- **Decisions/Proposals**: 제안 하나당 파일 하나, 상태(대기/승인/거부/체결) 필드 보유,
  평가노트·체결원장에 링크.
- **State**: 소수 파일, 자동화 판독 최적화 우선(Obsidian 열람은 부차적).
- **Knowledge**: 서술형, 자유롭게 링크·성장하는 문서.

### 폴더·연결 설계 원칙 (확정, 2026-08-04 — 앞으로 모든 Vault 구조에 적용)

Facts/Ledger 세분화 논의에서 나온 원칙을 전체 Vault로 일반화한다. State/Decisions/
Knowledge의 구체적 하위구조는 아직 안 잡는다(코드가 그 폴더를 실제로 쓰기 시작하는
해당 Phase — 퀀트/자산분배 트랙 로직·텔레그램 승인 흐름 등 — 에서 정한다) — 다만 그때도
아래 두 원칙은 그대로 적용한다.

1. **폴더는 "쓰는 시점에 이미 확정된 것" 기준으로 나눈다.** 나중에 확정되는 값(예:
   계좌 귀속)을 기준으로 폴더를 나누면, 그 값이 확정되는 순간 파일을 옮겨야 하는데
   이벤트 로그·기록은 한번 쓰면 옮기지 않는 게 원칙이다. 그런 값은 frontmatter 필드로
   비워뒀다가 나중에 채우고, 필요하면 Dataview 쿼리로 재조회한다.
2. **서로 참조해야 하는 파일은 frontmatter에 Obsidian 위키링크(`[[파일명]]`)로
   연결한다.** 예: Proposal이 승인·체결되면 그 결과 Execution 파일을 가리키는 필드를
   채운다, PositionJournal이 자신을 만든 Proposal·자신에 딸린 Execution들을 링크한다.
   폴더 계층으로 관계를 표현하지 않고(파일이 여러 관계를 동시에 가질 수 있어 계층 하나로
   못 담음) 필드로 명시적으로 연결한다.

### 기존 Trading Agent 허브와의 관계 (확정 — critic 리뷰 TIER 2 대응)

물리적 위치는 이미 확정됐다 — "Vault 물리적 위치·동기화 (확정)" 절 참고: 기존 Trading
Agent 허브(`profile/playbooks/learning/skills`)와 완전히 분리된 새 독립 경로에 Vault를
만든다.

**정본 이원화 해소**: 전략 원칙(펀더멘털 기준·매수매도 원칙 등)의 진짜 정본은 **새 Vault
Knowledge로 완전히 이관**하고, 기존 Trading Agent 허브는 **은퇴**시킨다 — 이관 완료 후
허브 쪽 파일은 더 이상 갱신하지 않는다. "옵시디언에 모든 기록이 있어야 한다"는 핵심
원칙과 가장 일치하는 선택이다. 만약 banana-portfolio 외 다른 시스템이 이 허브를 계속
참조하고 있다면, 그 시스템 쪽 이관도 별도로 필요하다 — 실제 구현(마이그레이션) 단계에서
확인할 사항.

## Firestore 미러

- 원본이 아니라 **캐시**. Vault State/Ledger가 바뀔 때마다 로컬 자동화가 전체를 재생성해
  덮어씀(부분 병합 없음 — 부분쓰기 버그 방지).
- 탭당 문서 1개: `mirror/home`, `mirror/holdings`, `mirror/allocation`, `mirror/dividends`,
  `mirror/profits`, `mirror/trades`, `mirror/latestReport`.
- 인증: 지금 `useGoogleSheets.js`와 동일한 구글 OAuth(GSI) 패턴을 재사용 — 코드 자산은
  GitHub Pages에 공개해도 안전하고(데이터 없음), 실제 데이터는 Firestore 보안규칙으로
  본인 계정만 읽도록 제한.
- 도입 배경: 리포지토리가 퍼블릭이라 Vault 데이터를 git에 직접 올릴 수 없고, 모바일에서
  대부분 확인하는 사용 패턴 때문에 로컬 전용(집에서만 열람)은 부적합 → "공개 코드 + 인증된
  클라우드 데이터"라는 v1의 검증된 무서버 패턴을 유지하되, 시트 대신 중첩 JSON에 적합한
  Firestore로 교체.

## 트리거 주기 (재정리, 2026-08-04)

> ⚠️ **옛 서술 폐기**: "장중 정기 폴링(장시작/매시정각/종가)"은 개별종목을 인트라데이로
> 감시하던 구버전 설계(추세추종·급락감지 등, 전부 폐기됨)의 잔재였다. 지금은 두 트랙
> 다 배치·스케줄 기반(자산분배=분기, 퀀트=월간)이라 인트라데이 감시 대상 자체가 거의
> 없다 — 실제로 뭐가 언제 필요한지 트리거 종류별로 다시 정리한다.

| 트리거 | 주기 | 용도 |
|---|---|---|
| **검문소 가격이탈 체크** | 폴링 아님 — 주문 **실행 시점 1회** 조회 | 이미 승인된 제안을 체결하기 직전, 제안 당시 가격과 크게 벗어나지 않았는지만 확인("안전장치 계층" 절) |
| **거시 오버레이 지표**(Faber 이평·금리차·DXY·VIX·유가) | **1일 1회** | 장중 시시각각 볼 필요 없는 매크로 지표. 의미있는 변화 감지 시에만 "거시 오버레이 전술 조정 제안" 발송 |
| **자산분배 분기 리밸런싱** | 분기 1회(스케줄) | 5/25 밴드 이탈 확인 |
| **퀀트 월간 리컨스티튜션** | 월 1회 말일(스케줄) | 팩터 순위 재계산 |
| **신규 현금 배분**(신규, 아래 "텔레그램 사용 흐름" 절 참고) | **이벤트 기반**(카카오 배당·매도체결 알림 누적 50만원↑) | 폴링이 아니라 실제 현금이 생겼다는 이벤트가 트리거 |

준비돼 있다. 별도 시간대 처리 로직이 필요한 지점 자체가 없다.

## 브로커 API 연동 범위

이번 설계 범위에 **포함**. v1의 KIS(한국투자증권) Open API 연동 자산(레이트리밋 처리 등)을

**장기 전략(오너 확인)**: NH·삼성증권 계좌도 매수/매도 자동화가 검증되면 한국투자증권(KIS)
API로 이전 검토 중. 계좌가 KIS로 통합될수록 아래 "카카오 알림 파싱"에 대한 의존도는
자연히 줄어든다(API 직접조회가 파싱보다 근본적으로 더 신뢰할 수 있는 소스이므로) — 파싱
파이프라인은 **과도기 다리**로 설계하고, 오래 유지할 것을 전제로 과잉설계하지 않는다.

## 카카오 알림 → Vault 파싱 파이프라인

### 전체 구조 (확정)

```
증권사 카카오 알림 → Kakao-Notification 안드로이드 앱 (변경 없음)
                            │
                            ▼
                  구글시트 "알람" 탭 (임시 중계소로 격하 — 더 이상 데이터 저장소 아님)
                            │
                            ▼  Mac 로컬 자동화가 주기적으로 읽음 (매시간, 기존 launchd 주기 계승)
                  기존 정규식 파서 그대로 재사용
                  (NH·삼성·한국투자 브로커별 — 체결/배당/펀드적립/금현물/예수금/환전 6종)
                            │
                            ▼
                  Vault Facts/Ledger에 이벤트당 파일로 기록 (멱등 dedup 키 유지)
                            │
                            ▼
                  처리 완료된 "알람" 행은 시트에서 정리(삭제/처리됨 마킹)
```

**핵심 결정**: Kakao-Notification 안드로이드 앱은 **수정하지 않는다** — 지금처럼 알림 원문을
구글시트 "알람" 탭에 그대로 적재. 구글시트는 더 이상 데이터 정본이 아니라 **폰→Mac으로
원문을 넘기는 임시 우편함**일 뿐이다(장기적으로 Drive 동기화 폴더 파일 방식으로 대체 검토
가능하나, 지금은 안드로이드 앱 변경 비용을 피하려고 시트를 그대로 씀).

**파싱 로직 승계**: v1 `scripts/jobs/parse-notifications.mjs`의 증권사별 정규식 파서
(NH투자증권·NH투자증권 해외·삼성증권·한국투자증권, 체결/배당/펀드적립/금현물/예수금앵커/
환전 6가지 패턴)는 이미 실전 검증된 자산이라 그대로 이식한다. 바뀌는 것은 **쓰기 대상**뿐 —
기존엔 체결내역/배당금 등 다른 시트 탭에 썼다면, 이제는 Vault Facts/Ledger에 이벤트당
파일로 쓴다.

**멱등성 유지**: v1이 이미 여러 차례 사고를 겪으며 다듬어온 dedup 키 체계(체결=날짜|구분|
종목명|수량, 배당=시각_금액 uniqueKey 등)를 그대로 계승 — 이 키들은 Vault 파일명 또는
frontmatter의 고유키 필드로 옮겨 동일한 재실행 안전성을 보장한다.

**알람 시트 처리 후 정리**: v1 코드 주석에서 이미 확인된 사실 — "알람은 외부 Kakao 앱이
관리해 과거 알림이 사라진다"(안드로이드 앱 자체가 오래된 알림을 자체 회전/삭제함). 즉 이
시트는 태생적으로 영구 저장에 부적합한 휘발성 우편함이다. 그래서 ①처리 주기를 촘촘히
유지(매시간)하고 ②처리 즉시 Vault에 영구 기록해 우편함이 비워져도 데이터가 안전하게
남도록 하는 기존 설계 원칙을 그대로 따른다.

## 앱 사용 체계 — 텔레그램·판테온·대시보드의 역할 분리

기본 그림: **텔레그램 방(판테온)에서 말을 거는 주체는 Zeus.** 대시보드 앱은 숫자만 보여주는
별도 채널이고, 판단·질문·승인은 전부 텔레그램에서 일어난다.

### 텔레그램 상시 응답 기술 메커니즘 (확정 — 실제 플러그인 코드 조사 기반)

지금 설치된 텔레그램 플러그인(`~/.claude/plugins/.../external_plugins/telegram/server.ts`)의
실제 동작을 코드로 확인했다. 두 가지 방향이 완전히 다르게 동작한다.

**인바운드 (Frank → Zeus: 질문·승인·부서 직접호출)**
- 플러그인 README에 명시: "메시지가 오면 서버가 그 메시지를 **당신의 Claude Code 세션**으로
  전달한다." 즉 메시지마다 새로 뜨는 헤드리스 호출이 아니라, **`claude --channels
  plugin:telegram@claude-plugins-official`로 띄운 세션 단 하나**가 실시간으로 메시지를 받는
  구조다. 텔레그램은 봇 토큰당 `getUpdates` 소비자를 한 개만 허용하므로 세션도 하나만 존재
  가능(동시에 두 개 못 띄움).
- 이 세션이 안 떠 있으면 응답이 안 온다. 텔레그램 서버가 짧게는 큐잉해주지만, 결국 이 세션이
  다시 연결돼야 밀린 메시지가 전달된다.
- **따라서 상시 응답 = 이 특정 세션을 24시간 띄워두고, 죽으면(크래시·재부팅) 자동 재시작하는
  감시 체계가 필요**하다. 지금 launchd로 다른 무인 잡을 돌리는 것과 같은 방식(launchd
  `KeepAlive`)으로 이 세션도 감시 대상에 추가한다. 세션은 반드시 이 프로젝트 디렉토리
  컨텍스트(`CLAUDE.md`·`.claude/agents/*`)를 물고 뜬다.
- 세션이 재시작되더라도 판단에 필요한 상태(Vault·`memory/*.md`·`worklog.md`)는 전부 파일에
  있으므로 대화 맥락 유실이 문제되지 않는다 — 오히려 이 구조 때문에 "세션이 아무 때나 재시작
  될 수 있다"는 전제가 원래도 강제돼 있었다(PANTHEON.md §5, 부서는 작업 시작 시 memory
  파일을 읽는다).

**아웃바운드 (시스템 → Frank: 아침브리핑·제안·경보 등 선제 알림)**
- `reply` 도구는 플러그인이 설치·설정(`~/.claude/channels/telegram/.env`의 봇 토큰)돼 있으면
  `--channels` 플래그와 무관하게 **어떤 Claude Code 실행에서도** 사용 가능해 보인다(MCP 서버
  자체는 플러그인이 켜져 있으면 항상 기동됨, `.mcp.json`이 무조건 `bun run start`).
- 즉 가격폴링·카카오알림파싱·리스크모니터·주간리포트 같은 **기존 launchd 헤드리스 잡들이
  각자 알아서 `reply`를 호출**해 선제 메시지를 보내면 된다 — 상시 세션과 무관.

**발견된 제약 — 인라인 버튼 불가**: 이 플러그인에 `InlineKeyboard`/`callback_query` 코드가
있긴 하지만, **Claude Code 자체의 "이 도구 실행해도 될까요?" 권한요청 전용**이다(harness가
쏘는 `permission_request` 알림 전용 배선, 고정 포맷 "🔐 Permission: {tool_name}"). 어시스턴트에
노출된 도구는 `reply`(텍스트+파일)·`react`(고정 이모지)·`edit_message` 3개뿐이라 **임의
비즈니스 버튼(승인/거부)을 보낼 수 없다.**

→ **매수/매도 승인은 텍스트 답장 방식으로 재확정**(위 "텔레그램 승인 UX" 절 갱신). Frank가
제안 메시지에 "승인"/"거부"라고 답장하면 상시 세션이 해석해 처리. 메시지 상태변화(edit로
결과 반영)는 버튼이 없어도 `edit_message` 도구로 그대로 구현 가능 — 제안 원문 메시지를
"[승인] 승인됨 (2026-08-23 14:32 KST)"으로 수정하는 방식은 유지된다(✅ 이모지는
2026-08-23 전면 제거·대괄호 태그로 교체 — 아래 실제 구현 각주 참고).

> ⚠️ **실제 구현 완료(2026-08-23, `scripts/lib/telegram.mjs` `editTelegramMessage` +
> `scripts/lib/proposal-flow.mjs` `buildProposalStatusEditText` + `scripts/tools/
> process-telegram-reply.mjs`)** — 승인/거부 처리 직후 원본 제안 메시지를 편집해
> `[제안]` 태그를 `[승인]`/`[거부]`로 바꾸고 결정 시각(KST)·거부사유(있으면)를 덧붙인다.
> 편집은 append가 아니라 전체 텍스트 재구성(Bot API 제약)이라, 원본 사실(facts)·사유
> (reason)를 proposal 레코드에서 다시 조립한다. 편집 실패(예: 원본이 48시간 지나 Bot
> API 편집 제한에 걸림)는 승인/거부 처리 자체를 막지 않고 로그만 남긴다.

### 판테온 조직 재설계 — 5부서 수평 체제 + 투자실행협의체

추세추종 신호 전담 부서로 신설해 5부서 체제로 확장한다. 5부서는 **수평 동등** — Hermes나
Apollo의 안건이 항상 Athena·Themis를 거쳐야 하는 수직 구조가 아니다. 각 부서는 자기
소관 안건을 스스로 종합해 Zeus에게 직접 올리고, Zeus는 그 보고를 승인·판단만 한다.

```
5개 부서 (수평 동등): Hermes · Kairos · Athena · Themis · Apollo
├─ 각자 소관 안건은 부서가 직접 종합해 Zeus에게 보고/제안
└─ Zeus는 그 보고를 승인·판단만 한다 (종합·조사는 이미 부서가 끝낸 상태로 올라옴)

```

선호 등)을 염두에 둔 개념이라 리밸런싱·거시오버레이에는 그대로 안 맞는다. 자산분배
트랙에서는 **"위험선호도·배분원칙과의 정합성"**으로 재정의한다 — 예: 최근 저널링에서
Frank가 불안감을 표한 시점에 유독 큰 폭의 리밸런싱·틸트가 제안되면 Apollo가 그 어긋남을
짚는다. 판정 형식은 기존과 동일(【정합성】합치/상충/중립 【근거】§3·확정 성향 인용
【신뢰도】상/중/하), 다만 참조하는 "성향"의 범위가 개별종목 취향이 아니라 위험 감내도·
배분 철학으로 좁혀진다.

**Zeus의 역할 재정의**: 부서 산출물을 비판적으로 검토·종합하던 기존 정의에서, **이미
완성된 안건을 승인/반려만 하는 최종 게이트**로 좁힌다. 종합·조사·근거 취합은 부서(투자실행
안건은 Athena, 그 외는 각 소관 부서)의 몫이다. 여러 부서가 걸치는 애매한 안건이 생겼을 때
Zeus가 직접 알아보러 다니는 상황 자체가 설계 결함 — 그런 안건은 반드시 담당 부서(또는
투자실행협의체)가 정해져서 종합까지 끝낸 뒤에만 Zeus에게 올라와야 한다.

### 신규 데이터 유형과 담당 부서

기존 체결·평가 데이터 외에, Vault Knowledge에 아래 3가지를 추가 수집한다:

| 데이터 유형 | 담당 부서 | 수집 방식 |
|---|---|---|
| 자유 저널링(생각·감정 기록) | Apollo | 텔레그램 자유 텍스트 → 성향 노트로 구조화 |

| 외부자산(은행·카드 지출) | Hermes | **월 1회 텔레그램 수동 캡처로 확정**(아래 근거 참고) |

**외부자산(은행·카드 지출) 수집 방식 확정**: 뱅크샐러드 같은 앱과의 직접 API 연동은
당초 후보였으나, 한국에서 개인 프로젝트가 은행/카드 거래 데이터를 프로그램으로 가져오려면
보통 앱 자체 공개 API가 아니라 금융결제원의 오픈뱅킹·마이데이터 체계(사업자 등록·인증
절차 수반)를 거쳐야 한다는 현실적 장벽이 있다. 이 데이터가 애초에 "투자판단과 직결되지
않는 후순위" 항목이라는 점을 감안해, 그 복잡도를 감수하지 않고 **월 1회 Frank가
텔레그램으로 카테고리별 지출액을 간단히 보고 → Apollo가 Knowledge에 기록**하는 방식으로
단순화했다. API 연동 없이 규제·인증 복잡도 전혀 없이 바로 가능.

### 위탁 레거시 개별종목 전환 — 시스템 관여 없음 (확정, 2026-08-02)

**오너 결정**: 위탁에 남아있는 레거시 개별종목(삼성전자·SK하이닉스·메리츠금융지주·

시스템 기능은 **만들지 않는다** — 개별종목 하나하나를 시스템이 분석하는 건 "개별종목
관련은 전부 퀀트 트랙으로 넘긴다"는 트랙 경계 원칙에도, 이 자산군 자체가 결국 소멸될
레거시라는 점에도 맞지 않는 불필요한 구현 낭비라는 판단.

**남는 것**: "위탁 개별종목은 결국 전량 ETF로 전환한다"는 **방향**(원칙 3의 2단계 전환
계획)만 설계 문서에 남기고, 그 실행의 **시점·순서·트리거는 전부 오너의 재량**이다.
전환이 실제로 일어나면(매도 체결) 카카오 알림 파싱으로 자동 기록되는 것은 그대로 유지
(이건 개별종목 "분석"이 아니라 이미 확정된 체결 기록 파이프라인이라 별개).

### 메시지 형식 — 부서 라벨 + Zeus 판단 코멘트

텔레그램에는 부서명 라벨을 그대로 노출한다(`[투자전략실 Athena] ...`). 부서 보고 뒤에는
**항상 `[Zeus]` 판단 코멘트**가 따라붙어, 그 부서 의견을 수용했는지/기각했는지와 근거를
명시한다. Frank가 "왜 이 제안이 나왔는지"뿐 아니라 "Zeus가 왜 그걸 받아들였는지"까지
한 대화에서 다 볼 수 있게 하는 것이 목적.

예시 형태:
```
[투자전략실 Athena] 삼성전자 매수 제안 — 근거: ...
[리스크관리실 Themis] 검증 통과 — 근거: ...
[Zeus] 승인 대기 — Athena·Themis 근거 모두 타당, 진행하려면 "승인", 취소하려면 "거부"로
답장해주세요.
```

Frank가 그 메시지에 **답장(reply-to)으로 "승인"/"거부"**를 텍스트로 보내면, 상시 세션이
`reply_to` 메시지 ID로 어느 제안에 대한 응답인지 식별해 처리한다(인라인 버튼 불가로 텍스트
답장 방식 채택 — 위 "텔레그램 상시 응답 기술 메커니즘" 참고). 처리 후 **원본 제안 메시지를
`edit_message`로 수정**해 상태를 반영한다(`[승인] 승인됨 (2026-08-23 14:32 KST)` 형태로
태그·시각 반영, 위 "텔레그램 상시 응답 기술 메커니즘" 절의 실제 구현 각주 참고) — 이 부분은
버튼 여부와 무관하게 그대로 구현 완료(2026-08-23).

### 부서 직접 호출

Frank는 텔레그램에서 특정 부서를 직접 지목해 부를 수 있다(예: "카이로스, 삼성전자 추세
어때"). 이때는 Zeus 경유 없이 해당 부서가 직접 응답 — 기존 Claude Code `/athena` 슬래시
호출과 같은 성격의 열람성 대화(게이트 미발동, PANTHEON.md §3 "Frank 직접 호출" 원칙을
텔레그램에도 그대로 적용).

## 구현 메모 (설계 단계에서 미리 남겨두는 기술 노트)

- **상시 세션 감시**: `claude --channels plugin:telegram@claude-plugins-official`를
  banana-portfolio-v2 디렉토리에서 실행하는 launchd job(KeepAlive: true) 필요. 기존
  `scripts/launchd/`의 다른 잡들과 같은 위치·패턴으로 등록.
- **봇 토큰 단일 소비 제약**: 텔레그램이 `getUpdates` 소비자를 토큰당 1개만 허용 — 실수로
  같은 세션을 중복 실행하면 409 Conflict 발생(`server.ts` 로그 참고). 감시 스크립트가 중복
  실행을 막아야 함.
- **제안↔답장 매칭**: Frank의 "승인"/"거부" 답장은 `reply_to`(원본 제안 메시지 ID)로 식별.
  `reply_to` 없이 그냥 "승인"만 보낼 경우의 폴백 규칙(예: 가장 최근 미처리 제안으로 간주)을
  실제 구현 시 정해야 함.
- **인라인 버튼은 재사용 불가로 확인됨**: `InlineKeyboard`/`callback_query`는
  `notifications/claude/channel/permission_request`(harness의 도구실행 권한요청) 전용
  배선이라 비즈니스 버튼으로 못 씀 — 나중에 "그때 왜 버튼을 안 썼지" 재조사하지 않도록 여기
  기록해둠. 버튼이 정말 필요해지면 플러그인 확장(`server.ts`에 새 MCP 도구 추가) 또는 별도
  봇 프로세스 신설이 필요.
- `[Zeus]` 코멘트는 부서 보고를 받은 직후 별도 메시지(또는 같은 메시지에 이어붙이는 방식)로
  발송 — 나중에 실제 구현 시 "부서 보고 1개 메시지 + Zeus 코멘트 1개 메시지"로 나눌지,
  하나의 메시지에 합쳐 보낼지 결정 필요.
- 부서 직접 호출(예: "카이로스, ~") 파싱은 메시지 시작 부분의 부서명 키워드 매칭으로 우선
  단순 구현 가능 — 이후 자연어 의도 분류로 고도화 여지.
- 논리훼손(B) 경보는 "리스크 경보"와 발송 우선순위가 다르다고 명시됨 — 알림 채널/우선순위
  체계(예: 텔레그램 알림음 on/off, 메시지 상단 고정 등) 설계 시 구분 필요.
- **Google Drive 동기화 충돌 위험**: 로컬 자동화가 State 파일(보유종목·잔고 등)을 매시
  덮어쓰는데, Drive 동기화가 이걸 다른 기기 변경과 충돌 처리할 수 있음(같은 파일이 양쪽에서
  거의 동시에 바뀌면 "충돌 사본" 생성 위험). 완화안: ①Facts/MarketPolls(가장 쓰기가 잦은
  롤링 원자료 폴더)는 애초에 안드로이드 동기화 앱 대상에서 제외(사람이 폰에서 볼 이유가 없는
  폴더이므로) ②State 파일은 자동화 전용으로 취급하고 사람은 폰에서 읽기만 하는 규칙을 지킴
  (폰에서 State 폴더를 직접 편집하지 않음).
- Mac 쪽 Google Drive 마운트 경로 확정 필요(예: `~/Google Drive/내 드라이브/banana-vault/`) —
  실제 구현 시 로컬 자동화의 쓰기 대상 경로 상수로 사용.
- 안드로이드 동기화 앱(FolderSync/Autosync 등) 선택·설정은 구현 단계에서 진행.
- **카카오 알림 파싱 담당 부서는 Hermes**(v1 `JOB_DEPARTMENT` 매핑 `parse-notifications:
  'hermes'`와 동일 원칙 계승) — 원자료 수집이므로.
- v1 dedup 키(체결=`날짜|구분|종목명|수량`, 배당=`시각_금액` uniqueKey 등)를 Vault
  frontmatter의 고유키 필드로 그대로 옮겨 멱등성 유지 — 새로 설계하지 말고 이식.
- "알람" 시트의 처리 완료 행 정리 방식(즉시 삭제 vs "처리됨" 표시 후 별도 정리)은 구현 시
  결정 — 삭제가 더 단순하지만 사고 발생 시 원문 재조사가 안 되는 트레이드오프 있음.

### 원칙 1 — 전체 위험 수준: 생애주기 이론 (Bodie-Merton-Samuelson)

**핵심 논리**: 미래 근로소득 자체가 채권처럼 작동한다. 40세로 앞으로 벌 소득이 많이
남아있으면 그게 이미 안전자산 역할을 하므로, **금융자산 쪽은 오히려 성장자산 비중을
높게 가져가도 총위험은 균형**이 맞는다.

**근거**: Bodie, Merton & Samuelson(1992, *Journal of Economic Dynamics and Control*).
실제 업계 검증: Vanguard·Fidelity 타겟데이트펀드(수백만 명 자금 운용) — 은퇴까지
약 25년 남은 투자자는 **주식(성장자산) 비중 80~90%대** 구간. Vanguard는 90/10에서
출발해 은퇴 후에도 계속 낮추는 "through-retirement" 방식.

### 목표 배분 % — 산출 방법론 (2026-08-01 확정 → 2026-08-01 오너 피드백으로 방법론 전환)

> ⚠️ **아래 Vanguard 글라이드패스 기반 82% 계산은 정본에서 대체됐다**(같은 날 오너
> 피드백). 무엇이 왜 바뀌었는지 순서대로 기록한다 — 나중에 "왜 이론값을 버렸지"
> 재검토할 필요 없게.

리츠 20% 사례였는데, 채권도 우연히 같은 자리에 옴 — 문제 아니라 오히려 깔끔함). 유일한
주의점은 **금 10%가 무수익 자산치고는 비중이 있는 편**(일반적 포트폴리오 관행의 상단)
이라는 것 — 다만 Frank가 이미 두 계좌에 걸쳐 금현물·금ETF를 보유해온 기존 선호와
일치하므로 이례적이지 않다.

**⚠️ 성장자산 비중 차이 — 명시적으로 짚어야 함**: 최종 정본의 성장자산(국내+해외주식)
= **60%**다. 원칙 1(생애주기이론)이 계산한 82%와 **22%p 차이**가 난다. 82%는 이론적
유도값, 60%는 오너가 이미 체계적으로 운영해온 실제 비율을 라운드로 정리한 것 — 오너가
후자를 명시적으로 채택했으므로 이 문서의 정본은 **60%(위 표) 기준**으로 바뀐다.

**원칙 1(생애주기이론)·Vanguard 글라이드패스 계산은 폐기하지 않고 배경 이론으로 보존**
(위 절 그대로 유지) — "왜 82%를 안 썼는지"를 나중에 다시 조사하지 않도록 남겨둔다.

### 계좌 간 분배 — 세금 최적 우선순위 방식 (2026-08-01 확정, 오너 피드백으로 방법론 교정)

> ⚠️ **이전 버전(잔액 비례배분)은 세금 최적이 아니었다** — 오너가 직접 짚어 교정했다.
> 무엇이 잘못됐고 어떻게 고쳤는지 기록한다.

**교정 전 오류**: 채권·금·국내주식·해외주식을 "계좌 capacity에 비례해 같은 비율로
나눈다"고 했었다. 이건 산술적으로 단순할 뿐 세금 관점에서 틀렸다.

**교정 근거**: 연금저축은 인출 시 모든 수익을 **연금소득세 3.3~5.5%로 뭉뚱그려
과세**한다. 즉 연금저축은 "이미 위탁에서 과세(최대 45% 누진)되는 자산"을 넣을 때만
이득이고, **"이미 위탁에서 비과세인 자산"을 넣으면 오히려 0%를 3.3~5.5%로 만드는
손해**다. 이 구분이 계좌 배치의 진짜 기준이다.

**연금저축에 넣을 진짜 이유가 있는가 — 자산군별 판정**:

| 자산군 | 위탁에서의 세율 | 연금저축에 넣으면? | 판정 |
|---|---|---|---|
| 배당ETF·리츠ETF | 15.4%(종합과세, 최대 45%) | 3.3~5.5%로 개선 | ✅ 반드시 연금저축 |
| 해외주식(국내상장 해외ETF 형태) | 위탁은 해외직접ETF로 22%(분리과세) | 3.3~5.5%로 개선(22%보다 유리) | ✅ 연금저축 우선 |
| 채권ETF | 위탁은 **개별채권**으로 0% 가능 | 3.3~5.5%로 **악화** | ❌ 원칙적으로 불필요(단, 개별채권 하나에 신용위험이 집중되는 문제의 분산 목적이라면 소액 유지 — 오너 확인, 2026-08-01) |
| 금ETF | 위탁은 **금현물**로 0% 가능 | 3.3~5.5%로 **악화** | ❌ 불필요 — 금은 발행사 리스크가 없어 채권과 달리 분산 논거도 약함 |
| 국내주식(형ETF·펀드) | 위탁은 이미 0%(비과세) | 3.3~5.5%로 **악화** | ❌ 불필요 — 연금저축에 있을 이유가 전혀 없음(오너가 직접 발견) |

### ⚠️ 위탁 내부 우선순위 — 통화 분산 반영 재교정 (2026-08-01, 두 번째 교정)

**오너가 추가로 짚은 것**: 위탁의 해외주식(테슬라·엔비디아·알파벳·MS 등)은 전부 **달러로
매수한 자산**이다 — 세금 효율만 보고 이 물량을 연금저축의 국내상장 해외ETF(원화 표시)로
옮기면, 포트폴리오 관점에서 의도치 않게 **달러 노출이 줄어드는 부작용**이 생긴다. 통화
분산은 세금 최적화와 다른 축이라 별도로 지켜야 한다.

**해결 — 위탁 해외주식은 "고정된 통화 분산 슬리브"로 취급**: 매도해서 연금저축으로
넘기지 않고, 개별종목(테슬라 등)만 분산된 미국 상장 ETF(**VOO·QQQ·SCHD**)로 교체하되
**달러 표시 금액 자체는 그대로 유지**한다.

**부작용 발견 → 위탁 내부 우선순위로 해결**: 위 방식을 그대로 적용하면 위탁 용량이
부족해져 채권(개별채권)을 대거 매도해야 하는 문제가 생겼다(세션에서 검증 — 위탁이
해외주식·국내주식·금을 전부 목표치대로 채우려 하면 채권 자리가 밀림). **오너가 위탁
내부 우선순위를 확정**: **해외주식(달러, 고정) → 채권 → 금현물 → 국내주식(잔여)**.
즉 국내주식이 위탁에서 가장 낮은 우선순위이며, 위탁 용량이 부족하면 국내주식부터
연금저축으로 넘어간다(채권·금이 밀리지 않도록).

**국내주식이 연금저축으로 넘어가도 괜찮은 이유(확인 완료, 2026-08-01)**: 연금저축이
보유한 국내주식(VIP한국형가치투자증권자투자신탁[주식], KoAct K수출핵심기업TOP30액티브)
둘 다 실제로 **국내주식형으로 분류되는 상품**이다 — KoAct는 운용사 자체가 "국내주식형
상품으로 연금 계좌에서도 투자할 수 있다"고 명시하고, VIP한국형가치투자는 "국내 주식을
주요 투자대상으로" 하는 [주식]클래스 펀드다. 즉 **위탁에 있든 연금저축에 있든 매매차익
과세가 동일(비과세)** — 국내주식은 어느 계좌에 두어도 세금 손해가 없으므로, 용량이
부족할 때 가장 먼저 넘겨도 되는 자산군이라는 오너 판단이 근거를 갖춘다.

**최종 결론(2026-08-02, 채권 쪽 실행 제약 반영 재확정) — 연금저축이 담는 것**: 배당ETF·
리츠ETF 100% + 채권ETF 조정분(**위탁 개별채권은 만기까지 보유해야 해서 손대지 않고,
채권 쪽 조정은 전부 연금저축이 흡수** — 오너 확인, 2026-08-02) + 국내주식 잔여분(위탁
용량 초과분) + 해외주식 잔여분(위탁의 달러 슬리브를 뺀 나머지, 국내상장 해외ETF로).
**금은 지금 보유 수준 그대로 유지**(즉시 정리하지 않고 점진적으로 위탁 쪽으로 몰아갈
예정, 목표 시점 미정).

**위탁이 담는 것**: 해외주식(달러, VOO·QQQ·SCHD로 고정, 통화분산 목적) + **채권(개별채권,
만기까지 그대로 유지 — 매수·매도 안 함)** + 금(연금저축 보유분을 뺀 나머지, 금현물) +
국내주식(남는 용량만큼).

**계좌를 실제로 어떻게 옮기나 — "이체"가 아니라 "각자 내부 재투자"**: 연금저축은
중도 인출 시 세액공제 클로백(16.5%)·소득세가 붙어 **계좌 밖으로 현금을 뺄 수 없다**.
따라서 계좌 간 조정은 실제 이체가 아니라: 각 계좌가 **자기 자금으로 내부에서만** 매도·
매수해 목표 비중에 맞추는 **두 계좌의 병행 거래**다. 세션에서 검증한 결과 두 계좌 모두
매도액=매수액이 자체적으로 맞아떨어진다(위탁 채권 유지·연금저축 금 유지 기준 — 위탁
총 매도=매수 약 810만원, 연금저축 총 매도=매수 약 797만원, 2026-08 잔액 기준).

**국내·해외주식 세부 비중**(예: 국내 자산군 안에서 정확히 몇 %가 어느 종목에)은 여전히
구현 단계 대상이나, 계좌 배치 우선순위 자체는 이제 확정이다.

> ⚠️ **이 우선순위의 성격 명확화(2026-08-04)**: 위 "해외주식→채권→금현물→국내주식"
> 순위는 **위탁·연금저축을 옛 구조에서 새 목표구조로 옮기는 전환기 전용 규칙**이다 —
> 어느 자산군을 어느 계좌에서 먼저 덜어낼지에 대한 **일회성 마이그레이션 순위**이지,
> 전환이 끝난 뒤 새로 생기는 현금을 어떻게 쓸지 정하는 **상시 규칙이 아니다.** 후자는
> 아래 "신규 현금 배분 원칙" 절에서 별도로 다룬다 — 두 질문을 섞으면 안 된다.

### 신규 현금 배분 원칙 (신규, 2026-08-04 확정)

전환이 끝난 뒤에도 배당·매도체결로 새 현금은 계속 생긴다. 이때 "무엇을 살지"는
고정 공식이 아니라 **그 시점의 실제 비중을 보고 판단**해야 한다 — 판단에 하드코딩을
금지하는 이 프로젝트의 원칙과 일치("판단에 하드코딩 금지" 원칙 참고).

**흐름**:
1. **Hermes(기계적 계산)**: 현금이 쌓인 그 계좌(위탁 또는 연금저축) 안에서, 자산군별
   "목표비중 대비 현재비중 갭"을 계산한다 — 분기 리밸런싱의 5/25 밴드 판정 로직을
   그대로 재사용, 새 로직을 만들지 않는다.
2. **후보 제한**: 그 계좌가 세금상 담을 수 있는 자산군으로만 후보를 좁힌다(위탁=해외
   상장ETF직접보유·개별채권·금현물·국내주식형ETF, 연금저축=배당ETF·리츠ETF·채권ETF·
   해외주식형ETF — "원칙 2" 계좌별 역할표 참고).
3. **Athena(종합 판단)**: 갭 크기·후보군을 받아 어디에 얼마씩 배분할지 최종 판단한다.
   갭이 가장 큰 자산군 하나에 몰아줄 수도, 여러 자산군에 나눌 수도 있다 — 고정 비율이
   아니라 재량. 갭이 비슷하면 위 "위탁 내부 우선순위"(전환기 규칙)를 **참고 지표(타이
   브레이커)**로만 쓸 수 있다.
4. **발송**: 텍스트 답장 승인 방식으로 텔레그램 제안("텔레그램 사용 흐름" 절의 "신규
   현금 배분 제안" 유형 참고) — 사유(어느 자산군이 왜 갭이 큰지)를 함께 명시.

**트리거**: 배당·매도체결로 생긴 미투자 현금이 계좌당 **누적 50만원 이상**일 때만
제안을 발송한다(카카오 알림 이벤트가 트리거, 폴링 아님) — 소액 배당마다 알림이 뜨는
것을 막기 위한 문턱값(오너 확정, 2026-08-04).

### 새 방식 vs 기존 방식 — 무엇이 다른가 (오너 요청, 2026-08-02 설명 보강)

**기존에 하던 방식(v1 습관)**: 위탁과 연금저축이 **각자 6개 자산군을 전부 조금씩** 갖고
있었다(위탁: 채권25·국내30·해외30·배당5·리츠5·금5, 연금저축: 국내30·해외30·채권15·
금10·배당10·리츠5). 두 계좌가 "같은 모양의 축소판 포트폴리오"를 각자 운영하는
방식이었다 — 어느 계좌에 뭘 넣을지는 세금을 계산해서 정한 게 아니라(이미 이전 감사에서
"오너가 임의로 정했다고 인정"됨 확인), 그냥 두 계좌 모두 골고루 갖추자는 논리였다.

**새 방식(이번에 확정)**: 전체 목표(20/10/5/5/30/30)는 **하나**뿐이고, 어느 계좌에 뭘
넣을지는 **세금 규칙에 따라 자산군마다 다르게** 정해진다 — 두 계좌가 같은 모양을
반복하는 게 아니라 **서로 다른 역할을 분담**한다:
- **배당·리츠**: 예전엔 위탁에도 있었으나(5%씩), 이제 위탁엔 **전혀 없음** — 전부 연금저축.
  위탁에선 배당소득세(최대 45% 누진)를 물지만 연금저축은 3.3~5.5% 고정이라 옮길 이유가
  명확했다.
- **국내주식·금**: 예전엔 두 계좌에 나눠 있었으나, 이제 **위탁에 최대한 몰림** — 위탁은
  이미 비과세(개별채권·금현물·국내주식형은 전부 0%)라, 굳이 연금저축에 넣으면 3.3~5.5%
  세금을 새로 만드는 셈이라 손해였다.
- **채권**: 위탁의 개별채권(삼척블루파워12)은 **만기까지 그대로 유지**(실행 제약,
  2026-08-02 확정) — 조정이 필요한 부분은 연금저축의 채권ETF 쪽에서 흡수한다.
- **해외주식**: 위탁은 "달러 그대로"(VOO·QQQ·SCHD, 통화분산 목적으로 고정) + 연금저축이
  나머지(국내상장ETF, 3.3~5.5%가 위탁의 22%보다 유리) — 유일하게 두 계좌 모두에 의미
  있게 남는 자산군이다.

**한 줄 요약**: 예전엔 "두 계좌가 각자 완결된 축소판을 들고 있었다"면, 이제는 "위탁 =
이미 세금이 없는 것들의 창고, 연금저축 = 세금 혜택이 진짜 있는 것만 모으는 창고"로
역할이 나뉘었다. 운영 방식(분기 점검·거시 오버레이)은 이전에 확정한 그대로 유지 —
이번 논의는 "얼마씩 나눌지"만 다시 정한 것이지 "어떻게 관리할지"는 바뀌지 않았다.
(단, F-Score 개별종목 전환 관리는 이후 별도로 완전히 제외됨 — "위탁 레거시 개별종목
전환 — 시스템 관여 없음" 절 참고.)

### 원칙 2 — 계좌 배치: 한국 세금 메커니즘 기반 자산배치이론

**출발 이론**: Dammon, Spatt & Zhang(2004, *Journal of Finance*) — 세제혜택계좌와
과세계좌 사이 자산을 어떻게 나눠야 세후 부(富)가 최대화되는지 다루는 정본. 미국에서는
"채권=세제혜택계좌, 주식=과세계좌"가 결론이지만, **그 결론을 만드는 메커니즘 자체가
한국에서는 다르다** — 한국은 채권이 아니라 "종합과세로 누진되는 배당소득 여부"가
기준선이다.

**한국 세금 구조 (2026-08 기준, 조세특례제한법·소득세법 확인 완료)**:

| 세금 유형 | 해당 자산 | 성격 |
|---|---|---|
| **비과세 매매차익** | 국내주식·국내주식형ETF, **개별채권**(소득세법 §16·§94 열거 안 됨), **KRX 금현물**(조특법 §126의7 — 부가세도 면제, 단 실물인출 시 10% 부가세 발생) | 정액(0%), 금융소득종합과세 미포함 |
| **분리과세 22%** | **해외상장 ETF 직접보유**(VOO·QQQ 등), 양도소득세, 연 250만원 공제 | 정액, 금융소득종합과세 **미포함** — 자산이 커져도 세율 고정 |
| **배당소득세 15.4%** | 국내상장 해외주식형ETF·**채권ETF**·**금ETF**·리츠ETF (전체 수익이 소득으로 과세) | 금융소득종합과세 대상(연 2천만원 초과 시 누진 6~45%) |

**결론 — 계좌별 역할(확정)**:

| 계좌 | 담는 것 | 원칙 |
|---|---|---|
| **위탁** | 국내주식형 ETF + **해외상장 ETF 직접보유**(VOO·QQQ 등) + **개별채권**(기존 삼척블루파워 등 유지) + **KRX 금현물**(실물 인출 안 함) | 전부 **정액세/비과세** — 자산 규모가 커져도 세율이 안 오름 |
| **연금저축** | 채권ETF·금ETF·리츠ETF·배당ETF + **국내상장 해외주식형ETF** | 세금이연 + 인출세 정액(3.3~5.5%)이라 종합과세 누진 문제 자체가 안 생김. "위탁에서 세는 새는 자산"의 피난처 |
| **ISA** | 배당주(국내·해외)·리츠·채권 분산(기존 결정 유지) | 저율과세(9.9%) + 순가치 손익통산 — 배당소득 성격 자산에 적합, 위 원칙과 정합 |
| **IRP** | TDF 유지 (변경 없음) | 범위 밖 |

> ⚠️ **금현물의 실제 거래 계좌는 위탁과 별개다(사실 기록, 2026-08-05, 오너 확인)**:
> 위 표의 "위탁 = ... + KRX 금현물"은 **세금·자산배분 분류상** 위탁 소속으로 취급한다는
> 뜻이다 — 그러나 **실제 매매·보유는 별도의 금현물 전용 계좌**를 통해 이뤄진다(위탁
> 계좌번호와 다른 계좌). 지금은 관리 방식을 바꾸지 않는다(오너 확정 — 그대로 유지).
> 다만 계좌 귀속을 실제로 다루게 될 단계(State/Holdings 설계, 카카오 알림 계좌번호
> 매핑, KIS 실주문 API 연동)에서 "금현물 알림이 위탁(205-01) 계좌번호로 온다"고
> 섣불리 가정하면 안 된다 — 실제로는 5번째 계좌(금현물 전용)에서 온다. 자산배분 계산
> (목표비중 갱신)에는 위탁 소속으로 합산하되, 계좌 잔고·체결 조회는 그 별도 계좌를
> 따로 다뤄야 한다는 사실만 여기 남겨둔다.

**ISA 담당 부서 — Athena(재확정, 2026-08-04)**: 2026-08-02엔 "관리 부서 없음"으로
확정했으나, 오너가 재검토를 요청해 뒤집었다 — 이유는 두 가지.

1. **이중노출 공백 발견**: 목표비중(20/10/5/5/30/30)이 "위탁+연금저축 합산에만" 적용되고
   ISA가 계산에서 완전히 빠져 있는데, ISA가 담는 자산(배당·리츠·채권)이 연금저축의
   담당 자산군과 그대로 겹친다. ISA 잔액이 크면 시스템이 보여주는 "인컴자산 10%"보다
   **실제 총자산 기준 인컴자산 노출이 훨씬 클 수 있는데, 아무 부서도 그 차이를 보고
   있지 않았다.**
2. **왜 새 부서가 아니라 Athena인가**: Athena·Kairos의 분리 기준은 **전략(방법론) 축**이다
   — 자산분배(목표비중 리밸런싱)와 퀀트(팩터랭킹 기계매매)는 서로 다른 투자 방법론이라
   계좌도 분리했다. 반면 ISA는 새로운 방법론이 아니라 **Athena가 이미 위탁·연금저축
   두 계좌에 걸쳐 쓰고 있는 "원칙 2 — 계좌 배치(세금 메커니즘 기반)" 방법론의 세 번째
   계좌 버킷**일 뿐이다. 새 부서를 만들면 하나의 세금최적화 전략(원칙 2)을 두 부서가
   나눠 갖게 돼 방법론이 쪼개지고, Hermes 데이터공급·Themis 리스크검증 라인도 그 부서용
   으로 중복 신설해야 한다 — 3년 뒤 연금계좌로 흡수·소멸하는 회전 계좌 하나를 위해
   정당화되지 않는 비용.

**Athena의 확장된 ISA 역할(2026-08-04)**:
- **배당전략·보유내역 분기점검**(기존 위탁·연금저축 분기 점검과 같은 주기) — ISA
  내부 종목 교체는 이 점검에서 필요시 제안, 강제 리밸런싱은 아님(ISA는 손익통산
  구조상 잦은 회전이 오히려 불리할 수 있어 신중히 판단).
- **3계좌 합산 노출 보고(신규)**: 분기점검 시 위탁+연금저축+ISA **3계좌 합산 기준**
  배당·리츠·채권 실제 비중을 별도로 계산해 보고한다. 단, **목표비중(20/10/5/5/30/30)
  계산 자체는 여전히 위탁+연금저축만 대상**(줄 806 그대로 유지) — ISA만큼 위탁/연금저축
  매수량을 자동으로 줄이지 않는다. 즉 **이중노출을 자동 보정하지 않고 오너에게 보이게만
  한다** — 최종 판단은 오너 재량(Zeus 의사결정 범위 원칙과 일치).
- 3년 만기 시점의 연금계좌 일괄이전 제안(원칙 3의 2단계 전환 계획)은 기존 그대로
  Athena가 1회성으로 처리.

**중요 — 기존 보유 개별채권·금현물은 "product 제약"이 아니라 "세금 최적화"였다**:
당초 "연금저축이 이 상품을 못 담아서 위탁에 둔다"는 상품 가용성 문제로만 보였으나,
확인 결과 **개별채권·KRX 금현물의 매매차익은 애초에 비과세**라 위탁에 두는 것 자체가
정답이었다. 같은 자산군(채권·금)이라도 **위탁=직접보유(비과세), 연금저축=ETF(세금이연)**
로 상품이 갈리는 것은 우연이 아니라 이 원칙의 자연스러운 결과다.

**해외주식 노출이 두 계좌에 걸치는 이유**: 위탁의 해외상장 ETF 직접보유(VOO 등, 22%
분리과세)와 연금저축의 국내상장 해외주식형 ETF(세금이연)는 같은 해외주식 노출이지만
**담는 방식에 따라 계좌가 갈린다** — 자산이 커질수록 위탁 쪽(분리과세, 종합과세 무관)이
유리해지는 구조.

> ⚠️ 이 결론은 미국 이론(Dammon-Spatt-Zhang)의 "표면적 결론"(주식류=과세계좌)과 닮아
> 보이지만 **완전히 다른 메커니즘**으로 도출된 것이다 — 미국은 "주식 양도세 이연 혜택
> vs 채권 매년 이자소득세"의 대비, 한국은 "국내주식·직접보유자산의 비과세 vs 펀드/ETF
> 배당소득세의 종합과세 누진"의 대비. 이 차이를 반드시 기록해둔다 — 나중에 "왜 한국인데
> 미국 이론 그대로 안 썼지" 재검토할 필요 없게.

### 원칙 3 — 납입 제약을 반영한 단계적 전환 계획

**확인된 제약(국세청·소득세법 §59-3 확인 완료)**:
- 연금저축+IRP **합산 연 1,800만원**이 전체 납입 상한
- 그중 세액공제 대상은 연금저축 단독 600만원, 합산 900만원까지
- **900만원~1,800만원 구간도 세액공제만 없을 뿐 납입은 가능** — 과세이연 혜택만 보려는
  추가납입 전략으로 이미 실무에서 쓰임
- 현재 자동적립(연금저축 월 50만원=연 600만원, IRP 월 25만원=연 300만원, 합산 연
  900만원)이 이미 세액공제 한도를 다 쓰고 있어, **추가로 넣을 수 있는 여력은 연
  최대 약 900만원**(1,800만−900만)

**ISA 만기 전환의 특수성**: ISA 만기 후 60일 이내 연금계좌로 이전하면, 그 금액은
**위 1,800만원 연간 한도와 완전히 무관한 별도 lump sum**이다(조특법 §91의18). 전환액의
10%(최대 300만원)를 추가 세액공제로도 받는다.

**결론 — 2단계 전환 계획**:
1. **1단계(지금~ISA 만기 전, 약 3년)**: 연금저축·IRP는 연 900만원 한도 내에서 목표
   자산군 구성으로 점진적 재배치. 위탁은 기존 개별종목 매도(수익실현)금액을 국내주식형
   ETF·해외상장ETF·개별채권·금현물로 순차 전환.
2. **2단계(ISA 만기 시점)**: ISA 잔액을 연금계좌로 일괄 이전 — 연간 한도 밖이라 즉시
   목표 비중에 크게 근접 가능.

### 추가 900만원/연 여력 — 채우는 순서 (확정, 2026-08-01)

**어느 계좌로**: 전액 **연금저축**으로 간다 — IRP는 "TIGER TDF2045 유지, 변경 없음(범위
밖)"으로 이미 확정(원칙 2 결론 테이블 참고)이라 자산군 재배치 대상이 아니다. IRP는 자동
적립분(월 25만원) 외에 추가 납입을 고려하지 않는다.

**재정리(2026-08-01)**: 이전 정리는 "위탁에 비과세 대안이 있는가"라는 단일 축으로
순위를 매겨, 서로 다른 성격의 두 질문(①이 자산군을 굳이 ETF로 담을 필요가 있는가 ②
담기로 했다면 몇 번째로 채우는가)을 뭉뚱그렸다. 이 둘을 분리한다.

**① 필요성 필터 — 위탁에 이미 비과세 대안이 있는가**: 채권은 위탁의 **개별채권**
(비과세), 금은 위탁의 **KRX 금현물**(비과세)이 이미 대안을 제공한다 — 그래서 이 둘은
"꼭 필요하지는 않은" 후보군으로 분류된다. 단, 개별채권은 특정 발행사(예: 기존 삼척
블루파워)에 신용위험이 집중되므로, **분산 목적의 채권ETF를 소액 병행하는 것 자체는
배제하지 않는다** — 중복이 아니라 보완이다. 리츠·배당·국내상장 해외주식형ETF는 위탁에
상응하는 비과세 대안이 없어 이 필터를 통과한다(리츠·배당은 ISA와 경쟁, 해외주식형은
위탁의 해외상장ETF직접보유와 경쟁하지만 "자산이 커질수록 위탁 쪽이 유리해지는 구조"이므로
지금 여력은 연금저축 쪽에 두는 게 자연스럽다).

**② 우선순위 — 매년 확정적으로 새는 세금의 크기**: 필터를 통과한 자산군 사이에서는,
분배소득(배당·이자·FFO)이 **매년 실제로 지급돼 그해 바로 과세되는 금액**이 클수록
연금저축 밖에 두었을 때 손해가 즉시 발생하므로 우선순위가 높다.

- **리츠ETF가 최상위**: REIT은 전 세계적으로 이익의 대부분을 의무적으로 배당해야 하는
  법적 구조라(한국도 동일 원칙) 분배율이 구조적으로 높다 — 이건 특정 상품의 수익률
  추정이 아니라 REIT이라는 자산군 자체의 규제적 특성이라 근거가 견고하다.
- **배당ETF가 그다음**: 고배당 전략 ETF는 분배율이 리츠보다는 낮지만 꾸준히 발생한다.
- **국내상장 해외주식형ETF가 가장 낮음**: 성장 중심 지수(미국 대형주·나스닥 등)를
  추종하는 상품은 분배가 거의 없고 수익 대부분이 미실현 자본이득이라, 매도 전까지는
  당장 새는 세금이 작다.

⚠️ **채권ETF의 위치는 확정하지 않는다**: 이자소득은 매년 100% 과세된다는 점에서 배당ETF
못지않게 시급할 수 있지만, ①필요성 필터에서 이미 낮은 순위군으로 분류됐고 ②실제 이자율
수준(현재 시장금리)과 배당ETF 분배율을 직접 비교해야 정확한 우선순위가 나오는데 그
비교는 지금 근거 없이 단정할 수 없다(§8 원칙) — **구현 단계에서 실제 분배율 데이터로
확정**한다.

**⚠️ 상충 하나 명시 — "당장 새는 세금" vs "장기 이연효과의 절대 크기"**: 국내상장
해외주식형ETF는 당장 새는 세금은 가장 적지만, 장기 기대수익률이 가장 높아 **나중에
쌓일 누적 과세대상 이득 자체는 가장 클 수 있다**. 즉 이 절이 채택한 "매년 확정적으로
새는 세금" 기준과, "장기 이연 효과의 절대 크기" 기준이 반대 방향을 가리킨다. 지금은
전자(더 보수적이고 즉시 손실을 막는 기준)를 기본값으로 채택하되, 실제 기대수익률
데이터가 갖춰지면(구현 단계) 두 기준을 정량 비교해 재검토할 수 있다.

**결론 — 채우는 순서**: ①리츠ETF → ②배당ETF → ③국내상장 해외주식형ETF → ④채권ETF·
금ETF(필요성 필터 통과 못함 — 분산 보완 목적 소액 편입만, 채권과 금 사이 순서는
구현 단계 데이터로 결정).

> ⚠️ **프레임 수정 완료(2026-08-01)**: 위 순서는 원래 "연금저축·IRP에 연 900만원까지
> **추가 납입(lump sum)**이 가능하다"는 전제로 짠 것이었으나, 오너 확인 결과 **연금저축은
> 회사를 통한 월 50만원 고정 자동납입이 유일한 경로**라 목돈 추가납입 자체가 불가능함이
> 확정됐다(개인이 증권사 앱으로 직접 추가입금하는 경로도 없음). **우선순위 로직(리츠→
> 배당→해외주식형→채권/금)은 그대로 유효**하되, 적용 대상이 "여윳돈 lump sum"이 아니라
> **"매달 나가는 고정 50만원의 상품별 배정 비중"**으로 바뀐다 — 즉 연금저축 펀드 변경/
> 추가설정 화면에서 매달 들어가는 50만원 중 몇 %를 리츠ETF·배당ETF·해외주식형ETF·
> 채권ETF·금ETF에 각각 배정할지를 이 우선순위대로 정하면 된다. 정확한 월별 배정 비율
> (예: 리츠 X%, 배당 Y%...)은 위 "지금 vs 목표" 금액 차이(구현 단계에서 정확히 계산)에
> 맞춰 다음 회차에 확정한다.
>
> **위탁의 배당·리츠 ETF는 연금저축으로 이동하지 않는다(확정, 2026-08-01)**: 계좌 간
> 실물·현금 이동 경로가 없으므로, 위탁에서 매도한 배당·리츠 ETF 대금은 **위탁 자체
> 지정 카테고리(개별채권·금현물·국내주식형ETF·해외상장ETF직접보유)로 그대로 재투자**
> 한다. 리츠·배당주 카테고리의 계좌 간 부족분(연금저축 쪽 목표 미달)은 즉시 해소되지
> 않고, 위 월 자동납입 상품배정 우선순위를 통해 **시간을 두고 서서히** 채워진다 — 이
> 프로젝트가 이미 여러 번 확인한 "즉시 해결 아님, 점진적 수렴"과 같은 패턴이다.

**담당 부서(확정, 2026-08-02)**: 이 월 자동납입 상품배정 조정은 **Athena** 담당이다 —
리밸런싱안 수립과 성격이 같다(목표비중 대비 어떻게 채워나갈지의 판단).

**전체 성장자산(국내·해외 주식) 목표 비중 = 60%**(2026-08-01, 오너 지시로 방법론
전환 — 원칙 1 절 "목표 배분 % — 산출 방법론" 참고. 위탁·연금저축 기존 목표비율의

### Faber의 역할 — 5개 신호 중 유일하게 다른 층위 (오너 질문, 2026-08-02)

나머지 4개(금리차·DXY·VIX·유가)는 전부 **"거시경제/시장 전체의 위험 신호"**다 — 이
넷이 동시에 움직이면 "뭔가 큰 게 터졌다"는 뜻이다. **Faber는 성격이 다르다** —
거시 위험 신호가 아니라 **"지금 이 자산군을 들고 있는 게 맞는가"를 가격 그 자체로
판정하는 추세 필터**다.

- 나머지 4개: **왜** 위험한지(환율·금리·달러·유가라는 원인)를 본다
- Faber: **그래서 지금 국내주식·해외주식 ETF 가격이 실제로 어떻게 반응하고 있는지**
  (10개월 이동평균 대비 위/아래)라는 **결과**를 본다

즉 4개 거시신호가 "위험이 커지고 있다"고 말해도, 실제 자산군 가격이 아직 10개월
평균 위에 있으면(Faber 미이탈) 그건 아직 "이 자산군엔 반영 안 됨"이라는 뜻이라
섣불리 틸트하지 않는다. 반대로 거시신호는 잠잠한데 Faber만 단독으로 하향 이탈하면
"이 자산군 고유의 이유"(수급·개별 요인)로 해석한다. **5개를 같이 보는 이유가 바로
이 원인(4개)-결과(Faber) 교차 확인**이다 — 신용스프레드 하나를 더 넣는다고 이
구조가 좋아지지 않는다는 게 "5개면 충분하다"는 판단의 근거다.

**"국제정세"를 왜 전용 지수 하나가 아니라 조합으로 처리하나**: 오너 피드백의 핵심은
"보편적이고 심플한 논리"였다 — GPR처럼 계산 방식이 블랙박스인 전문 지수 하나에 기대는
것보다, **이미 알고 있는 3개의 대중적 지표가 함께 움직이는지**를 보는 쪽이 오너 스스로
"지금 이게 왜 뜬 신호인지" 검증할 수 있어 훨씬 투명하다.

**Frank가 언급한 "물가"는 어떻게 반영되나**: 별도 물가지수(CPI 등)를 새로 추가하지
않는다 — 물가는 이미 금리(중앙은행의 물가 대응이 금리에 반영됨)와 **이번에 추가한
유가**(원유는 물가에 직접 영향을 주는 최상류 원자재)에 흡수돼 있다. 유가 신호 자체가
물가 축의 가장 대중적인 대리지표 역할을 겸한다.

### 거시 오버레이 실행 프로토콜 (신규 확정, 2026-08-01)

> 위 절까지는 "어떤 신호를 계산하는가"만 정해져 있었다 — Frank가 실제로 텔레그램에서
> 무엇을 보고 어떻게 답장하면 뭐가 바뀌는지가 없어서, 개별종목 매수/매도만큼 구체적인
> 사용 흐름으로 보강한다.

**트리거 주기**: Faber 10개월 이동평균 신호는 **월 1회, 월말 종가 기준**으로 계산한다
(Faber 원 논문 방법론 그대로 — 월중 재계산은 신호가 아니라 노이즈만 늘린다는 게 그
방법론 자체의 전제). 금리차·DXY·VIX·유가는 기존 risk-monitor와 같은 **일 단위 폴링**을
그대로 재사용한다.

**소집 규칙**: 확정된 신호(Faber·금리차·DXY·VIX·유가, 총 5개) 중 하나라도 "의미있는
변화"(Faber는 이달 말 자산군별 이동평균 상·하향 크로스 발생 여부, 나머지는 기존
risk-monitor의 ±2σ 이탈 판정을 그대로 재사용)가 감지될
때만 **자산분배 트랙 투자실행협의체**(Hermes→Athena→Themis→Zeus, 위 "판테온 조직
재설계" 절 참고)가 소집된다. 아무 신호도 안 움직이면 소집 자체가 없다 — 매일 협의체를
여는 게 아니라 변화가 있을 때만.

**Athena의 판단 범위(재량, 새 임계값 발명 금지)**: "이 신호가 진짜 국면전환인가 노이즈
인가"를 종합 판단하고(위 "LLM 해석 영역" 표), 전환으로 판단되면 **전술적 틸트**(어느
자산군을 목표비중에서 얼마나·어느 방향으로 일시 이탈시킬지)를 제안한다. 이 틸트의
상한은 새로 정하지 않고 **이미 확정된 Swedroe 5/25 밴드를 그대로 재사용**한다 — 구조적
리밸런싱과 전술적 틸트가 같은 잣대를 쓰므로 "틸트는 왜 이 폭까지만 허용되는가"에 대한
근거가 자동으로 생긴다(§8 근거없는 임계값 금지 원칙과 정합).

**텔레그램 발송(선제, 아래 "텔레그램 사용 흐름" 표에 8번째 유형으로 편입)** — 예시:

```
[운영실 Hermes] 국내주식 ETF, 10개월 이동평균 하향 이탈 확인(2026-08월말 기준). 장단기
금리차·DXY·VIX·유가는 아직 정상 범위.
[투자전략실 Athena] 전술 조정 제안 — 국내주식 비중을 목표 대비 -5%p 일시 축소, 채권
비중 +5%p 확대. 근거: Faber 신호 단독 이탈이고 나머지 신호는 정상이라 "확정적
국면전환"보다는 "제한적 위험신호"로 판단, 5/25 밴드 상한까지만 조정.
[리스크관리실 Themis] 검증 통과 — 틸트 폭이 기존 리밸런싱 밴드 이내, 근거 정합.
[Zeus] 승인 대기 — 진행하려면 "승인", 취소하려면 "거부"로 답장해주세요.
```

**승인 이후**: 개별종목과 동일한 결정론적 검문소(가격이탈·보유정합성 등 — ETF 매매이므로
그대로 적용 가능) → 지정가 자동 발주 → 체결 시 Facts/Ledger 기록, Decisions/Proposals에
"거시 오버레이 틸트"로 표시(개별종목 Proposal과 구분).

**되돌림(unwind) 규칙**: 틸트의 근거가 된 신호가 반전되면(예: 국내주식 ETF가 다시
10개월 이동평균 위로 복귀) 같은 협의체가 재소집돼 **원래 목표비중 복귀 제안**을 별도
발송한다 — 틸트는 무기한 유지되지 않고 신호가 유지되는 동안만 존재하는 임시 상태다.
분기 리밸런싱 점검 시점 전에 신호가 반전되면 그때 되돌리고, 점검 시점까지 신호가
유지되면 정기 리밸런싱 점검과 자연 합류한다(아래 "분기 리밸런싱 점검" 절 참고).

### 투자철학 — 거래 기본개념 (확정, 2026-08-03)

> ⚠️ 아래 팩터·유니버스·구조 결정들이 실제로는 이 철학 정리보다 **먼저** 확정됐다(순서
> 역전). 뒤늦게 "왜 이 팩터가 작동한다고 믿는가"를 명시적으로 정리해보니 다행히 기존
> 결정들과 충돌은 없었다 — 이 절은 그 사후 정합성 확인 기록이다. 앞으로 퀀트 트랙에
> 새 규칙을 추가할 때는 이 철학을 먼저 통과시킬 것.

**믿음(오너 확정)**: 가격은 필연적으로 펀더멘털 가치로 수렴한다 — **평균회귀**.
추세추종이 아니다("한국 시장 증거" 절 — 한국 개별종목 모멘텀은 근거가 약하고 반전이
지배적이라는 결론과 일치).

**진입 개념(오너 확정)**: 순수 **상대(횡단면) 순위** 기반 — "코스피200+코스닥150 후보군
대비 얼마나 싼가"로 상위 10위를 고른다. 절대 저평가 기준(예: "OCF/P가 몇 이상")은 따로
두지 않는다 — 평균회귀 철학에서 중요한 건 "그 시점에 상대적으로 회귀 여지가 가장 큰
종목"이지 절대 수준이 아니다. 시장 전체가 비쌀 때도 상위 10위가 절대적으로는 비쌀 수
있다는 점을 오너가 인지한 상태에서, 자산분배 트랙의 거시 오버레이(Faber 이평·VIX 등)가
이미 시장 전체 밸류에이션 위험을 관리하므로 퀀트 트랙에 별도 절대기준을 추가하지
않기로 확정.

**청산 개념(재해석)**: 순위가 20위 밖으로 밀림 = 가격이 상대적으로 회복돼 더 이상 심하게
저평가가 아니게 됨(=수렴 진행) — 기존 버퍼존 매도 규칙은 임의의 회전율 절감 장치가
아니라 **평균회귀 철학상 타당한 청산 신호**로 재해석된다.

**포지션 규모(재해석)**: 동일가중 기준 ±50%, Kairos가 저평가 정도(순위 격차)로 재량
조정 — 회귀 여지가 클수록 비중을 키운다는 점에서 철학과 일치.

### 40M이라는 자금 규모가 만드는 물리적 제약

- **Statman(1987)**: 제대로 분산되려면 **최소 30~40종목** 필요("10종목이면 충분"은 오해)
- 40M ÷ 30종목 = **종목당 약 130만원**
- 그런데 한국에서 이상현상이 강한 곳은 **소형주**인데, 소형주는 130만원 주문도 호가
  스프레드로 슬리피지 발생 가능

→ **"이론 수익이 가장 큰 영역(소형주)"과 "실제 체결 가능한 영역"이 어긋난다.** 유동성
하한선(예: 최근 20일 평균 거래대금 기준)이 필수.

### 유니버스·유동성·종목수·포지션 사이징 (확정, 2026-08-03)

**유니버스**: 코스피+코스닥 전체 상장종목(관리종목·거래정지·SPAC 등 표준 클린업만
제외). Han, Lee & Kang(2020) 연구 자체가 코스피+코스닥 전체 대상이고, 가치효과가
가장 강한 소형주가 코스닥에 몰려 있어 제외하면 오히려 효과가 강한 영역을 잘라낸다.

**종목 수 = 10종목 이내(오너 확정)**: Statman(1987)의 "최소 30~40종목 분산" 기준과는
다른 방향이나, **이유가 있는 의도적 선택**이다 — 자산분배 트랙(80%)이 ETF로 이미 충분한
분산을 확보하고 있으므로, 퀀트 트랙(20%)까지 별도로 광범위하게 분산할 필요가 없다.
전체 포트폴리오 관점에서 보면 "80% 분산 + 20% 집중"이라 분산 효과 자체를 포기하는 게
아니라, 분산의 책임을 트랙 간에 나눈 것이다.

**포지션 사이징 = 동일가중 기준 ±50%, Kairos 재량(확정, 2026-08-03)**: 기존 리서치
결론("동일가중이 실무적으로 더 견고 — 과최적화 여지 적음")을 완전 대체하지 않고,
**동일가중을 기준선으로 삼되 Kairos가 OCF/P 점수 강도(순위뿐 아니라 점수 격차)를 보고
비중을 재량 조정**하는 방식으로 확정 — 오너가 "포지션 크기 결정도 판단 대상"이라고
명시(자유재량이 완전 무근거가 되지 않도록, 자산분배 트랙의 Athena 거시틸트가 5/25
밴드로 캡 씌워진 것과 같은 패턴으로 상하한을 둔다). 10종목 기준 동일가중 = 40M÷10 =
**400만원**, 실제 배정 범위 = **200만원~600만원**(동일가중의 50%~150%). 총합은 항상
40M원에 맞춘다(한 종목을 늘리면 다른 종목이 줄어드는 방식).

**유동성 하한 = 일평균 거래대금 30억원 이상(오너 확정)**: 실제 확인된 데이터로
추정했다 — 코스닥 시장 전체 일평균 거래대금(2026-07 기준) 약 6.1조원을 코스닥
상장종목수(약 1,700개)로 나누면 종목당 **평균 약 36억원/일**이 나온다. 다만 거래대금은
소수 인기종목에 쏠리는 분포라 **중위값은 이 평균보다 낮을 것으로 추정**되며(정확한
중위값은 KRX 원자료 접근 제약으로 확인 못 함, 정직하게 명시), 30억원은 이 평균값에
근접한 수준으로 오너가 직접 확정했다 — "종목당 매수금액의 20배"라는 참여율 기준
(400만원×20=8,000만원)보다 **훨씬 높은 절대 기준**이라, 실질적으로 이 30억원 기준이
1차 필터가 되고 참여율 기준은 자금 규모가 크게 커졌을 때만 작동하는 보조 안전장치로
남는다.

> ⚠️ **소형주 배제 효과 인지**: 30억원 기준은 코스닥 초소형주 상당수를 걸러낼 수 있다
> — 가치효과가 가장 강한 영역과 일부 겹치는 트레이드오프다. 다만 이건 "이론 수익 최대화"
> 보다 "실제 체결 가능성과 정상적으로 거래되는 종목만 담는다"는 오너의 명시적 우선순위
> 판단이다.

### 후보군 축소 — 코스피200+코스닥150 (확정, 2026-08-03)

**매달 전체 유니버스(유동성 통과 후 약 800~1,200종목 추정)를 전부 재계산하는 건 자원
낭비**라는 오너 지적으로, 재무데이터를 매달 새로 가져와야 하는 후보군 자체를
**코스피200 + 코스닥150 지수 구성종목(합계 350종목)**으로 축소한다. 임의의 숫자가
아니라 **한국거래소가 이미 운용 중인 대표지수의 구성종목을 그대로 재사용**하는 것 —
이 지수들의 구성종목 리스트는 이미 시가총액·유동성 기준으로 산출돼 정기적으로
공개되므로 새로 산출할 필요가 없다.

> ⚠️ **소형주 배제 효과가 한 번 더 겹친다**: 이 지수들은 시가총액 상위 종목 위주라,
> 위 유동성 필터(30억원)에 이어 **두 번째로 소형주를 배제하는 효과**가 생긴다 —
> 가치효과가 가장 강한 영역(소형주)에서 더 멀어진다는 뜻이다. 오너가 자원 절감을
> 위해 의식적으로 감수하기로 한 트레이드오프다.

### 바이어스 방지 규칙 (확정, 2026-08-03)

이미 "실무 기계장치" 표에 일반론으로 있던 두 항목을, 이번 설계(350종목 후보군·월 1회
리컨스티튜션)에 맞춰 구체적 규칙으로 확정한다.

**① 생존편향(Survivorship Bias) 방지**:
- **실전 운영**: 자동으로 안전하다 — 매달 그 시점에 실제로 존재하는 코스피200+코스닥150
  구성종목만 스캔하므로 생존편향이 낄 자리가 없다.
- **검증(백테스트) 단계에서만 문제가 된다**: "지금의" 코스피200/코스닥150 리스트가
  아니라 **"그 당시 실제 구성종목이었던" 과거 지수 편입 이력**을 써야 한다 — 지수도
  분기마다 종목이 바뀌고, 상장폐지·합병으로 사라진 종목은 현재 리스트에서 아예 안
  보이기 때문.
- **데이터 소스 확정(2026-08-04)**: 별도 유료 벤더(FnGuide·WiseFn·DataGuide) 조사 불필요
  — 이미 시가총액 데이터 소스로 채택한 **pykrx**가 그대로 해결한다. `pykrx.stock.
  get_index_portfolio_deposit_file(ticker, date)` 함수가 KRX 서버에 날짜를 직접 전달해
  **그 시점 기준 실제 구성종목**을 반환한다(소스 코드 확인 — `krx.get_index_portfolio_
  deposit_file(target_date, ticker)`를 그대로 호출, "현재 리스트를 필터링"하는 방식이
  아니다). 단, **2014-05-01 이전 데이터는 KRX 자체가 제공하지 않아 조회 불가** — 백테스트
  구간 설계 시 이 하한을 반영해야 한다.

**② 룩어헤드 바이어스(Look-ahead Bias) 방지**:
- 재무제표(OCF)는 **분기 마감일이 아니라 실제 공시일** 기준으로 반영한다 — OpenDart의
  공시일 필드를 신호 생성일로 사용, 재계산 시점(매달 말일) 이전에 **실제로 공시된**
  재무제표만 그 달 계산에 포함한다.
- 예: 2분기(4~6월) 실적은 마감일이 6월 30일이지만 실제 공시는 통상 8월 중순 — 7월
  말일 재계산 시점엔 아직 이 2분기 실적을 쓸 수 없고, 직전(1분기 이전) 공시 데이터로
  계산해야 한다.

### 국내 대중 퀀트에 대한 평가 (동료심사 아님 — 참고용)

- **강환국 슈퍼가치전략**(시총 하위 20% + PBR·PCR·PER·PSR 순위합산): 아이디어 방향은
  학술 근거와 일치(가치 + 소형주). 그러나 **백테스트 숫자는 신뢰 불가** — 2004~2016년
  기준 연 38~40%로 알려졌으나 **2016년 이후를 포함하면 연 16.97%로 급락**. 표본기간
  선택 효과가 컸다는 뜻. "채택할 뼈대"가 아니라 **"가설의 출발점"**으로만 취급.
- **젠포트·퀀트킹**: 탐색 도구로는 유용. 그러나 화면의 백테스트 곡선은 **수백~수천 조합 중
  사후적으로 잘 맞은 하나**일 가능성이 높다. 시도 횟수를 스스로 세지 않으면 다중검정
  보정이 불가능하다.

### 실거래 투입 전 검증 방법론

- **워크포워드 분석**: 5년 in-sample로 파라미터 확정 → 다음 1년 out-of-sample 측정 →
  윈도우를 앞으로 밀며 반복. **out-of-sample 구간 성과만** 최종 판단 근거로 사용
- **다중검정 문제**(Bailey & López de Prado 2014, *Deflated Sharpe Ratio*): 몇 개 조합을
  시도했는지 통제하지 않으면 관찰된 샤프비율의 유의성을 판단할 수 없다. **시도한 파라미터
  조합 수를 스스로 기록**하고, 많이 시도했을수록 채택 기준을 더 보수적으로
- **최근 1~2년은 반드시 out-of-sample로 남겨둘 것** — 규칙 확정 전까지 그 구간을 보지 않음
- **소액 실거래 3~6개월 병행 검증** 후 자금 확대 — 백테스트와 실거래의 괴리(신호 지연·
  슬리피지·데이터 정합성 버그)는 실제로 돈을 걸어보기 전엔 안 드러남
- 이 검증 절차는 이미 확정된 **섀도우모드**와 자연스럽게 맞물린다

### 백테스트 자체평가 기능 (확정, 2026-08-03)

**무엇을 검증하는가 — 개별 종목이 아니라 알고리즘 자체**: 이 기능은 "이번 달 상위
10종목이 좋은가"를 보는 게 아니다. **월 1회 리컨스티튜션 규칙 전체**(350종목 유니버스+
30억원 유동성 필터+OCF/P+버퍼존 10/20위+동일가중±50%)를 과거 몇 년간 그대로 돌렸다면
그 결과가 실제로 벤치마크보다 나았는지 — **방법론 자체의 유효성**을 검증한다. 개별
종목 스크리닝(리컨스티튜션, 매달 진행)과는 다른 층위의, 알고리즘 전체에 대한 성적표다.

**절차**:

```
[1단계] 워크포워드 검증
  5년 in-sample(파라미터 확정용) → 다음 1년 out-of-sample(실제 성과 측정)
  → 윈도우를 앞으로 밀며 반복. 최근 1~2년은 항상 out-of-sample로 남겨둠

[2단계] Node가 계산하는 성적표(결정론적 숫자, 판단 없음)
  - 연평균 수익률, 샤프비율, MDD(최대낙폭)
  - 코스피 대비 초과수익(벤치마크 비교)
  - Deflated Sharpe Ratio(다중검정 보정 — 시도한 파라미터 조합 수를 스스로 기록)

[3단계] 통과 판정(임의 숫자 대신 상대비교·기존 방법론 재사용)
  ① 벤치마크(코스피) 대비 초과수익이 있는가
  ② Deflated Sharpe Ratio가 통계적으로 유의한가(Bailey & López de Prado 방법론
     자체의 판정 기준)
  ③ MDD가 벤치마크보다 심하지 않은가

[4단계] 결과 처리
  통과 → 소액 실거래(섀도우모드) 3~6개월 병행 검증 → 실전 확대
  실패 → Zeus 보고, 실전 투입 보류, 파라미터 재검토
```

**재실행 시점(확정, 2026-08-03) — 둘 다 적용**:
1. **알고리즘 규칙이 바뀔 때마다**(유동성 기준·버퍼존 숫자·팩터 등 수정 시) — 규칙이
   바뀌면 그 새 규칙 전체를 처음부터 다시 검증
2. **정기적으로 분기 1회** — 규칙을 안 바꿔도 최신 데이터를 반영해 성과가 유지되는지
   재확인(자산분배 트랙의 분기 점검과 같은 리듬)

**담당 부서**: Hermes(과거 데이터 공급) → Kairos(백테스트 결과 종합·판정) →
Themis(과최적화 여부 재검증) → Zeus(승인) → 통과 시 섀도우모드 진입 — 기존 판테온
협업 패턴을 그대로 재사용, 새 프로세스를 발명하지 않는다.

### 팩터 선택 — 가치 단일 뼈대, OCF/P (확정, 2026-08-02)

**결론**: 퀀트 트랙은 **가치(Value) 팩터 단일 뼈대**로 시작한다. 퀄리티(수익성)는 한국
증거가 20개 중 5%만 유의해 사실상 안 통하고, 모멘텀도 다중검정 보정 후 27%(소형주
편중)로 약하다 — 이 프로젝트가 이미 §8 원칙(근거없는 조합 금지)으로 한 번 걸러낸
"합성 가설" 함정을 반복하지 않기 위해, 강한 팩터(가치 70%)에 약한 팩터를 섞지 않는다.

**가치 지표 = OCF/P(영업현금흐름/시가총액) 단일 지표**(오너 확정) — 복합 가치점수(PBR·
PCR·PER·PSR 순위합산 등, 강환국식)가 아니라 **이미 검증에서 가장 강했던 단일 지표
하나만** 쓴다. 복합점수는 노이즈를 줄이는 장점이 있지만 "각 지표를 몇 %씩 반영할지"라는
새로운 가중치 결정이 또 필요해지고, 이건 근거 없는 임의 결정(§8 위반)이 되기 쉽다 —
단일 지표는 그 자체로 이미 이 연구가 측정·검증한 값이라 가중치 논쟁이 생기지 않는다.

**저변동성**: 채택하지 않는다. KOSDAQ에서 강하다는 국내 연구가 있으나 "원문 재확인
필요"로 이미 남겨져 있던 미검증 항목 — 검증 전에 뼈대에 넣지 않는다.

**MSCI Quality의 운명**: **폐기**. 자산분배 트랙에서 용도가 사라진 뒤 퀀트 트랙 전용
후보였으나, 방금 확정한 원칙(퀄리티는 한국에서 5%만 유의)과 정면으로 배치돼 채택하지
않는다.

**MSCI Enhanced Value(PBR+선행PER+OCF/P 3지표를 z-score로 표준화 후 동일가중 1/3씩
합산)도 채택하지 않는다(재확정, 2026-08-03)**: 2026-08-03 세션에서 "OCF/P 단일지표를
이 3지표 조합으로 바꿀지" 재검토했으나 최종적으로 **단일지표 유지로 확정**했다. 이유:
MSCI Enhanced Value의 1/3씩 가중치는 MSCI가 **자기들 유니버스(글로벌 대형주 수백
종목·광범위 분산)에 맞춰 검증한 값**이지, 우리 상황(한국 350종목 후보군·10종목 집중·
월 1회 리밸런싱)에서 검증된 값이 아니다. "실제 운용되는 지수 방법론이니 안전하다"는
인상과 달리, **우리 데이터로 검증하지 않은 조합을 그대로 가져온다는 점에서 §8 원칙
(근거없는 임의 조합 금지)이 경계하는 것과 본질이 같다** — 검증 안 된 조합을 우리가
직접 만드는 대신 남이 만든 걸 빌려오는 차이일 뿐. 반면 OCF/P 단일지표는 정확히 우리
유니버스(한국 코스피+코스닥)에서 우리가 근거로 삼은 논문(Han·Lee·Kang 2020)으로
**직접 검증된** 값이고, 가중치 논쟁 자체가 생기지 않는다. 위 "투자철학" 절(평균회귀·
상대순위)과도 단일지표 쪽이 더 정합적이다.

> **백테스트 후보로는 보존**: 3지표 조합이 실제로 더 나은 성과를 내는지는 믿음이 아니라
> 데이터로 답할 문제다 — "백테스트 자체평가" 절(05 시뮬레이션 단계)에서 OCF/P 단일 vs
> 3지표 조합을 우리 데이터로 직접 비교하는 것을 향후 검증 대상으로 남겨둔다. 지금
> 채택하지 않는 것과 앞으로 시도해보지 않는 것은 다르다.

### ⚠️ 중대 방향 전환 — 추세추종은 채택하지 않는다 (2026-07-29)

이 프로젝트의 원래 "핵심 방향 4가지" 중 3·4번은 **추세추종을 타이밍 보완재로 테스트**
하는 것이었다. 2회에 걸친 문헌 리서치 결과 **증거가 그 방향을 지지하지 않아 채택하지
않기로 했다.** 원래 전제를 뒤집는 결정이므로 배경을 명시적으로 남긴다.

**기각 근거**:
1. **한국 개별주식에서 모멘텀은 작동하지 않는다.** 20년치 한국시장 연구가 일관되게
   "개별종목 모멘텀은 약하고 불안정하며 **반전(reversal)이 지배적**, 종목 단위 모멘텀
   전략은 실제로 언더퍼폼"이라고 보고(Kim&Byun 2011; Eom 2022; *Momentum and reversal
   effects in the Korean stock market* 1983~2023, Investment Analysts Journal 2024).
   모멘텀 개념의 창시자인 **Jegadeesh & Titman 본인들의 2023년 리뷰**에서도 한국 포함
   아시아 시장에서 2000~2020년 근거를 찾지 못했다고 보고.
2. **개별종목 단위 시계열 모멘텀은 글로벌하게도 근거가 약하다.** Huang, Li, Wang & Zhou
   (JFE 2020): 강한 통계량은 여러 종목을 묶은 pooled 회귀에서만 나오고, 종목별 회귀에선
   신뢰할 만한 증거가 거의 없다.
3. **역설적으로 Frank의 기존 본능이 증거와 더 잘 맞는다** — 한국은 반전장이므로
   급락매수·저점매수가 오히려 시장 구조에 부합한다.

**그 결과 이 레이어는 추세추종이 아니라 "펀더멘털 게이트 + 평균회귀 + 수급 + 변동성
관리"로 구성된다**(아래 구조 참고).

### 매수 게이트 1 — 품질 (MSCI Quality 방법론, 2026-07-31 확정)

학술 QMJ(약 15팩터)가 아니라 **MSCI가 실제 운용에 쓰는 3팩터판**을 채택한다. 방법론이
공개돼 있어 출처가 명확하고, 필요 데이터가 훨씬 적다.

| 팩터 | 정의 |
|---|---|
| **ROE** | 자기자본이익률 |
| **부채자본비율 (D/E)** | 재무 레버리지 |
| **이익변동성** | 최근 5년 EPS YoY 성장률의 표준편차 (낮을수록 좋음) |

각 팩터를 Z-score로 변환해 평균 → **품질 점수**. (참고: S&P 500 Quality는 ROE·발생액비율·
재무레버리지 3팩터로 유사하나 이익변동성 대신 회계이익 품질을 봄 — 5년 이력이 불필요해
더 가볍지만, 이번엔 MSCI판 채택.)

**비교 모집단(확정 — 2026-07-31)**: QMJ/MSCI는 원래 전체 시장 횡단면 순위 시스템인데
Frank는 롱온리로 대형우량주만 본다. → **시장별 시가총액 상위 100종목**을 모집단으로
삼아 Z-score를 자체 계산한다(분기 1회).

- **시장별 분리 필수**: 국내 100 + 해외 100을 **각각 별도로** Z-score 계산. 한 통에 섞으면
  통화·회계기준·시장구조 차이로 왜곡된다. MSCI도 Korea Quality와 USA Quality를 별도
  지수로 분리한다.
- **왜 대형주끼리 비교가 타당한가**: MSCI Quality 자신이 모지수(MSCI USA·MSCI Korea 등
  대형·중형주 집합) **안에서** Z-score를 계산한다 — 대형주를 대형주와 비교하는 것이 원
  방법론이다. 편법이 아니라 방법론 준수.
- **왜 100개인가**: Z-score는 표본이 작으면 극단값에 흔들린다. MSCI Korea 모집단이
  약 90종목, MSCI USA가 약 600종목 — 시장당 100개면 안정성과 계산 비용의 균형점.
- 품질은 분기 재무제표 기반이라 자주 변하지 않아 분기 1회 계산으로 충분하다.

> ⚠️ **해석상 주의(반드시 문서·보고서에 명시)**: 이 백분위는 **"시총 상위 100종목 내 상대
> 순위"**이지 **시장 전체 백분위가 아니다.** 이미 걸러진 집단 안의 순위이므로 "시장 상위
> 20%" 같은 전체 시장을 함의하는 표현을 쓰면 안 된다.

### 품질 컷오프 — 지수 제공사 값 차용 (확정, 2026-07-31)

감사에서 유일하게 미해소였던 "몇 점부터 통과인가"를 해결한다. **숫자를 새로 만들지
않고, 지수 제공사가 이미 쓰는 컷오프를 그대로 차용한다**:

| 지수 | 모지수 규모 | 선정 종목 수 | 비율 |
|---|---|---|---|
| MSCI World Quality | 약 1,500종목 | 약 300종목 | **20%** |
| S&P 500 Quality | 500종목 | 100종목 | **20%** |

서로 독립된 두 기관이 같은 20%에 수렴한다 — 임의값이 아니라 공개 방법론에서 인용 가능한
수치라 §8 원칙(근거 없는 임계값 금지)을 통과한다.

**적용**: 비교 모집단(시장별 시총 상위 100) 중 **품질 점수 상위 20종목 = Pool**.

> ⚠️ **비대칭 — 국내·해외 문턱 높이가 다르다**: MSCI Korea 모지수(약 90종목)는 우리
> 모집단(100종목)과 규모가 거의 같아 20%를 그대로 적용해도 자연스럽다. 반면 MSCI
> USA(약 600종목) 대비 우리는 **가장 큰 100종목만** 보고 그중 20%를 뽑으므로, 이미
> 초대형주로 추린 뒤 다시 상위 20%를 요구하는 셈이라 **해외 쪽 문턱이 실질적으로 더
> 높다.** 의도적 결정은 아니고 모집단 크기 차이의 부산물이므로 인지하고 있을 것 — 필요시
> 다음 회차에서 해외만 모집단을 넓히는 조정을 검토할 수 있다.

**왜 절대 점수(예: Z-score ≥ 0) 대신 비율을 택했나**: 절대 기준은 모집단 전체가 나빠지면
Pool이 텅 빌 수 있다(순수 상대평가 문제를 되레 절대기준으로 옮긴 것뿐). 비율 컷오프는 항상
Pool 크기가 일정(시장당 20개)해 운용이 예측 가능하고, 지수 제공사 관행과도 일치한다.

### 세 개념 구분 — 비교 모집단 / 관심종목 / Pool

혼동하기 쉬워 명시한다. 셋은 다르다:

| 개념 | 정의 | 누가 정하나 | 갱신 |
|---|---|---|---|
| **비교 모집단** | Z-score 계산의 **분모** — 시장별 시총 상위 100 | 자동(시총 순) | 분기 |
| **관심종목 리스트** | Frank가 **아는·투자 의향이 있는** 종목 | **Frank가 직접 관리** | 수시 |
| **Pool (매수 후보군)** | 관심종목 중 품질 컷오프를 **통과한** 종목 | 품질 점수가 결정 | 분기 |

즉 1단계 품질 게이트는 "Pool을 **발명하는**" 게 아니라 **Frank가 아는 종목 중 구조적으로
튼튼한 것만 남기는 필터**다.

### 갱신 주기가 다른 3개 층

```
[1층] 품질 (MSCI Quality 3팩터)  → "구조적으로 튼튼한 회사인가"   분기 갱신
[2층] 밸류에이션                  → "지금이 살 가격인가"           일·주 단위
[3층] 타이밍 (급락 감지 등)       → "오늘 사는 게 맞나"            일 단위
```

### 종목 발굴 — 기존 규칙 완화 (2026-07-31, 오너 확정)

> ⚠️ **이것은 기존 규칙의 변경이다.** `playbooks/active-evaluation.md` §8 가드레일에
> "❌ 추천 종목 발굴(stock screener) 금지 — Frank가 명시한 종목에 대한 평가만 한다"가
> 명시돼 있다. 구현 시 그 플레이북도 함께 개정해야 한다.

**변경 내용**: 발굴을 허용하되 **"검토 대상 제시"까지만**. 모순처럼 보이지만 흐름을 나누면
"모르는 회사엔 투자하지 않는다" 원칙과 양립한다:

```
발굴(품질점수 높은데 관심종목에 없는 종목)
   → "검토해볼 만합니다" 수준으로만 알림
   → Frank가 직접 알아보고 판단
   → Frank가 관심종목 리스트에 등록해야
   → 비로소 매수 파이프라인 대상이 됨
```

즉 발굴 결과는 **매수 후보가 아니라 학습·검토 대상**이다. 자동으로 모르는 회사를 사는
경로는 열리지 않는다.

**비용**: 사실상 없다. 비교 모집단(시총 상위 100)의 품질 점수를 어차피 계산하므로, 그
결과에 이미 모든 종목의 순위가 들어 있다 — 관심종목에 없는 고득점 종목을 골라내는 건
추가 연산이 거의 없다.

**발송 빈도**: 하루 1건 또는 주 1건 수준(오너 희망) — 구체적 빈도는 구현 시 조정.

**지수 편입은 참고 플래그로만(확정)**: QUAL(iShares MSCI USA Quality) 등은 전체 보유종목을
매일 무료 공개하므로 "MSCI 품질 스크린 통과" 여부를 공짜로·출처 명확하게 확인할 수 있다.
그러나 ①Frank의 후보 대부분이 이미 편입돼 있어 변별력이 약하고 ②**MSCI Korea Quality와
MSCI USA Quality는 서로 다른 모집단**이라 Z-score 분포가 달라 국내·해외를 한 잣대로
비교할 수 없다. → 판단은 자체 점수로 하고, 편입 여부는 제안서에 참고정보로만 표기.

**AQR은 개별종목 점수를 공개하지 않는다**(팩터·포트폴리오 수익률만) — 조사 완료, 재조사 불필요.

### 기존 5축 감사 결과 — 무엇을 버리는가

기존 5축(수익성·재무안정성·밸류에이션·현금흐름·모멘텀)을 감사한 결과 구조적 결함이
확인됐고, 뼈대 교체로 대부분 자동 해소된다:

| 감사에서 발견한 문제 | MSCI Quality 뼈대 도입 시 |
|---|---|
| 모멘텀 축(가격·매일 변동)이 펀더멘털 축(분기 변동)과 **동등하게 계산**됨 | ✅ 해소 — 품질에 모멘텀 없음. 타이밍은 완전히 별개 단계 |
| RSI·52주가 **축 판정과 특수 트리거에서 이중 계산**(서로 상쇄되는데 우선순위 규칙 없음) | ✅ 해소 — 매수 자격 판단에서 제외 |
| 밸류에이션 축 🟢 조건 안에 현금흐름 축 지표(FCF yield)가 들어가 **축 경계가 무너짐** | ✅ 해소 — 품질과 밸류에이션이 완전히 분리된 게이트 |
| ROE의 레버리지 왜곡을 걸러낼 장치 없음(ROIC는 learning에만 있고 미사용) | ✅ 해소 — D/E가 별도 팩터로 레버리지를 직접 감점 |
| "동종 평균 1.5배"인데 **동종 평균 데이터 출처가 없음**(LLM 추정 의심) | ✅ 해소 — 자체 계산 모집단으로 실제 Z-score 산출 |
| "🟢 3개 이상" 같은 **결론 규칙에 근거 없음** | ✅ 해소 — 지수 제공사 컷오프(상위 20%) 차용, 위 "품질 컷오프" 절 참고 |
| 배당성향을 성장주에도 동일 적용 | ✅ 해소 — MSCI Quality에 배당성향 없음(ISA 배당주 계좌는 필요시 별도 규칙) |

### 매수 게이트 2 — 밸류에이션 (미설계)

MSCI Quality는 **순수 품질 지표라 밸류에이션이 없다** — "좋은 회사인가"만 알려주고 "지금
살 가격인가"는 답하지 않는다. 따라서 밸류에이션 게이트가 별도로 필요하다.

근거: Novy-Marx(2013)는 수익성과 밸류에이션이 **서로 보완적**이며 "비싸지만 우량한 기업이
싸지만 부실한 기업을 이긴다"고 보고 — 두 축을 결합하는 것 자체가 문헌이 지지하는 구조다.

후보: Graham 방어적 투자자 7기준(절대 임계값→백분위 변환), 자기 5년 PER 밴드 위치.

### (참고) 폐기된 합성 가설 — 재검토 방지용 기록

아래는 2026-07-30에 만들었다가 위 방법론 전환으로 **폐기**한 내용이다. 개별 근거는
유효하나 조합이 검증되지 않아 뼈대로 쓰지 않는다. 다만 **타이밍 단계**(품질·밸류에이션
게이트를 통과한 뒤 "언제 살까")에서는 여전히 참고할 수 있어 기록만 남긴다.

"급락하면 산다"는 아직 가설이 아니다. **어떤 급락은 반등하고 어떤 급락은 계속 떨어지는지**
구분해야 진짜 가설이 된다.

**기존 O신호의 결정적 빈틈**: 현재는 `5일 낙폭 ≥ ATR 기대변동폭 2배 또는 RSI≤30`만 본다 —
**"왜 떨어졌는가"를 묻지 않는다.** 하락은 원인이 다르고 결과도 다르다:

| 하락 유형 | 평균회귀 하는가 |
|---|---|
| 유동성·수급 일시 불균형, 과잉반응 | ✅ 되돌아옴 |
| 시장 전체 하락에 동반 | ⚠️ 시장이 돌아오면 같이 |
| **기업 고유 악재(실적·공시·뉴스)** | ❌ **계속 간다** |

그리고 **펀더멘털 게이트로는 세 번째를 못 잡는다** — 게이트가 보는 재무제표는 분기
단위라 오늘 터진 악재는 몇 달 뒤에나 숫자에 나타난다. "떨어지는 칼날" 방어가 비어 있었다.

**정교화된 가설**:
> 가격이 그 종목의 정상 변동 범위를 크게 벗어나 하락했고, 그 하락이 **(a) 기업 고유의
> 새로운 부정적 정보 때문이 아니며 (b) 펀더멘털이 여전히 견고**하다면, 평균으로 회귀할
> 가능성이 높다.

**반증 조건(= 매수하지 않음)을 명시적으로 둔다**:

| 반증 조건 | 근거 |
|---|---|
| 실적 발표 직후 구간 | **PEAD(실적발표 후 표류)** — 재무학에서 가장 견고하게 재현된 이상현상 중 하나(Ball&Brown 1968; Bernard&Thomas 1989). 실적 서프라이즈 후 주가는 그 방향으로 몇 주~몇 달 표류하며 **반등하지 않는다** |
| 시장 대비 초과 하락이 큼 + 중대 공시 존재 | 정보 기반 하락 |
| 펀더멘털 게이트 실패 | 기존 원칙 |
| 밸류에이션이 이미 밴드 상단 | 싸서 사는 게 아님 |

### 매수 파이프라인 — 순차 흐름 (⚠️ 2026-07-31 뼈대 교체로 일부 재작성 필요)

> **상태**: 아래 **설계 원칙 3가지와 실행 순서 개념은 여전히 유효**하다(비용·탈락·의존성
> 순서는 뼈대와 무관하게 성립). 그러나 **3~5단계의 내용은 낡았다** — 당시엔 기존 5축을
> 전제했으나 이제 매수 자격 판단은 「게이트 1: MSCI Quality 품질점수 → 게이트 2:
> 밸류에이션」으로 바뀌었다. 1~2단계(급락 스크리닝·하락 원인 판별)는 자격 판단이 아니라
> **타이밍 판단**으로 위치가 재정의됐다. 게이트 2 설계가 끝나면 이 파이프라인 전체를
> 새 뼈대에 맞춰 다시 그린다.

**설계 원칙 3가지**(뼈대 교체와 무관하게 유효): ①싼 것 먼저(로컬 계산 → API → LLM)
②탈락 먼저(많이 걸러내는 조건을 앞에) ③의존성 존중(ATR 없이 상대화 불가).

```
[0] 트리거: 일봉 종가 후 1회 / 대상 = 보유종목 + 관심종목 리스트
         │
┌────────▼──────────────────────────────────────────┐
│ 1단계  결정론적 급락 스크리닝        (Node, 무료)  │
│  1-1  14개월 일봉 확보                             │
│  1-2  ATR(14) → 이 종목의 5일 기대변동폭            │
│  1-3  실제 5일 낙폭 계산                            │
│  1-4  낙폭 ≥ 기대변동폭 × N배 ?                     │
│       └ NO → 종료 (대부분 여기서 끝)                │
└────────┬──────────────────────────────────────────┘
         │ YES — 이 종목에게 이상한 하락
┌────────▼──────────────────────────────────────────┐
│ 2단계  하락 원인 판별 — "떨어지는 칼날" 배제 ★신규 │
│  2-1  실적발표 직후인가?          (날짜 비교, 무료) │
│       └ YES → 탈락 (PEAD)                          │
│  2-2  시장 대비 초과 하락은?      (지수 데이터)     │
│       · 시장 동반 → 개별악재 아님 → 통과            │
│       · 종목만 크게 → 개별요인 의심 → 2-3           │
│  2-3  중대 공시 존재?             (DART 조회)       │
│       └ 있으면 LLM이 중대성 판정(보수적) → 중대시 탈락│
└────────┬──────────────────────────────────────────┘
         │ 통과 — 유동성·과잉반응성 하락으로 판단
┌────────▼──────────────────────────────────────────┐
│ 3단계  펀더멘털 게이트 (기존 5축)     ※ 분기 캐시   │
│ 4단계  밸류에이션 위치 (PER 자기 5년 밴드)          │
│        · 하단 → 강한 근거 / 상단 → 탈락             │
│ 5단계  수급 확인 (국내주식만, KIS) → 참조정보 첨부  │
└────────┬──────────────────────────────────────────┘
┌────────▼──────────────────────────────────────────┐
│ 6단계  Athena 종합 판단 (LLM 본격 개입)             │
│ 7단계  포지션 크기 산정 (변동성 기반 + 500만원 분할)│
│ 8단계  Themis 리스크 검증 → 통과해야 상신           │
│ 9단계  Zeus 승인 → 텔레그램 제안                    │
│ 10단계 Frank "승인" → 결정론적 검문소 → 체결        │
└───────────────────────────────────────────────────┘
```

**LLM 개입 지점은 정확히 두 곳**: 2-3(공시가 있을 때만 조건부 호출)과 6단계(본격 종합).
1~5단계 대부분이 기계적 계산이라 대다수 종목이 1단계에서 종료되고 LLM 호출은 드물게
일어난다 — 앞서 확정한 "Node 2단 필터" 원칙과 맞물린다.

**스캔 대상(확정)**: 보유종목 + **관심종목 리스트**. 시장 전체 스캔은 하지 않는다(펀더멘털
검증이 안 된 종목까지 매번 처리하는 비용·위험 회피). → 관심종목 리스트는 Vault에 새로
관리해야 할 데이터다(아래 미결정 참고).

**공시 중대성 판정(확정)**: LLM이 판정하되 **보수적으로** — 중대성이 애매하면 탈락 쪽으로
기운다(놓치는 기회보다 칼날을 잡는 게 더 비싸다는 판단).

### 매도 파이프라인 — 흐름이 다르다

매도는 기회 탐색이 아니라 **보유 개별종목 전체 상시 감시**다.

```
[상시] 보유 개별종목 전체
    ├── 급락 감지 ──────→ ❌ 매도 아님. 펀더멘털 재점검 트리거로 전환
    │                        ├ 재점검 멀쩡 → 매수 파이프라인 1단계로 유입
    │                        └ 재점검 훼손 → 아래 1층으로
    ├── 펀더멘털 훼손(B신호) → 【1층】 매도 검토
    ├── 밸류에이션 밴드 상단  → 【2층】 부분 익절
    └── 변동성 급등          → 【3층】 매도 아님, 포지션 크기 축소
```

**핵심 원칙: 가격이 빠졌다는 것 자체는 매도 신호가 아니다.** 취향이 아니라 증거 기반
결론이다 — 한국은 반전 지배적 시장이라 약세에 파는 것은 체계적으로 불리하다. Frank의
"밀릴 때 무조건 파는 건 별로"라는 직관을 문헌이 뒷받침한다.

**급락이 두 파이프라인을 잇는 연결점**: 급락은 매도 트리거가 아니라 재점검 트리거이고,
재점검을 통과하면 오히려 매수 후보로 넘어간다(기존 O신호 철학과 일치).

### 변동성 기반 크기 조절 — 이 레이어에서 근거가 가장 강한 부분

**Barroso & Santa-Clara(JFE 2015)**: 모멘텀 전략을 **6개월 실현변동성** 기준 **연 12%
목표 변동성**으로 조절하니 샤프비율 **0.53 → 0.97**로 개선되고 모멘텀 크래시가 사실상
소멸. Daniel & Moskowitz(2016)가 동적 버전으로 재확인. **이 분야에서 구체적 숫자까지
검증된 거의 유일한 기법**이다.

⚠️ 단 범위 주의: 이 근거는 **모멘텀/추세 전략에 좁게 적용될 때** 강하다. Moreira &
Muir(2017)의 "모든 팩터를 변동성 관리하면 좋다"는 확장 주장은 Cederburg et al.(JFE
2020)이 103개 전략으로 검증했을 때 **실시간 구현 가능한 형태에서는 우위가 확인되지
않았다.** 따라서 이 기법을 시스템의 다른 모든 신호로 무비판적으로 확장하지 말 것.

### 남은 충돌·주의사항

1. **⚠️ 폴링 주기(미해결)**: "장시작/매시정각/종가"로 확정했으나 리서치는 이 계열 신호가
   전부 **일봉 종가 기준 검증**이며 장중 재계산은 "정보 추가 없이 거짓신호·휩쏘만
   증가"시킨다고 경고. 역할 분리(신호=일봉 1회, 장중 폴링=리스크 감시 전용)가 유력하나
   오너 판단 보류 중.
2. **52주 고점의 의미**: 현재 시스템은 52주 고점 근접을 **매도** 신호로 쓰지만(§4),
   George & Hwang(2004)은 오히려 향후 수익률을 **양(+)으로 예측**한다고 보고. 다만 위
   "가격만으로 매도하지 않는다" 원칙을 채택하면 이 충돌은 상당 부분 자동 해소된다.
3. **모멘텀 크래시 ↔ 급락매수**: Daniel & Moskowitz(2016)는 모멘텀 최악 손실이 **폭락 후
   반등 국면**에 집중된다고 보고. 추세추종을 채택하지 않기로 해 직접 충돌은 줄었으나,
   변동성 관리 층을 설계할 때 이 국면 처리를 고려할 것.
