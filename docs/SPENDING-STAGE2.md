# 소비 알림 2단계

원문 정본은 Vault `95_Etna/Spending/{year}/{date}.jsonl`이다. 수집 잡은 원문을 검증해 저장한 뒤 같은 폴더에 `{date}.summary.json`을 원문에서 재계산해 쓴다. 데일리 노트 `## 지출`과 헤르메스 아침·저녁 브리핑은 원문에서 그날 지출을 계산한다. 데일리 동선은 원문에서 확정 결제만 읽는다. 송금 판정 대기는 합계와 동선에서 제외한다. 온누리 결제대금 청구 알림은 승인 지출을 다시 청구한 것이므로 합계에서 제외하고 그 건수와 근거를 파생 요약에 남긴다. 삼성 온누리 **승인** 알림의 `결제대금에 미포함` 문구는 별도 청구가 아니므로 승인 금액은 지출에 포함하고 이 근거를 별도로 표시한다.

`95_Etna/Spending/settings.json`은 선택 파일이다. 오너 확인 후 `recipientDecisions` 배열에 수취 은행 `bank`, 계좌 끝 네 자리 `last4`를 넣는다. 가족 수취처로 확인했다면 `recipient`에 `휘영` 또는 `미네`를 지정하고, `status`를 생략하면 이체로 분류해 지출에서 제외한다. `status`는 `expense` 또는 `excluded`만 허용하며, 오너가 예외를 명시한 경우 `expense`로 지정할 수 있다. 기존 본인 계좌 이체는 설정 판정보다 우선하여 제외한다. 실제 수취 계좌 값은 Vault 설정에서만 등록하며 코드나 문서에 넣지 않는다. 미네 계좌 번호는 확인된 값이 없어 코드나 설정에 추정해 넣지 않는다. 다른 수취처는 설정에서 확인되지 않으면 계속 판정 대기다. 가족 제외 이체는 브리핑과 데일리 노트에 수취인과 금액만 표시하고 지출 합계에서 제외한다. 설정 변경 후 파생 요약은 다시 계산해야 한다.

기존 날짜의 요약은 `node scripts/tools/rebuild-spending-summaries.mjs`로 쓰기 없이 대상 건수를 확인한다. Vault 등록부에 파생 파일과 설정 파일을 등록하고 독립 검증을 마친 뒤에만 `--apply`로 생성한다. 이 도구는 원문 락 다음 요약 락을 잡고 원본 JSONL을 수정하지 않는다.

파서가 확인하지 못한 형식은 지출로 추정하지 않는다. 신한 교통카드와 뱅크샐러드 내보내기는 표본·별도 설계 전까지 대상이 아니다.

원문이 없는 날은 설정 파일이 손상되어 있어도 지출 없음으로 표시한다. 원문이 있는 날 설정 오류는 지출 계산을 실패시켜 운영 로그에 드러낸다. 저녁 브리핑은 다른 발송 사유가 있으면 원문이 없어도 `오늘 지출 알림 기록 없음`을 표시하며, 일정·요청·음성·지출 원문이 모두 없으면 기존의 미발송 정책을 따른다.

같은 금액·가맹점의 일반 승인과 온누리 승인은 별건으로 유지한다. 동일 카드·금액·가맹점이 3분 안에 서로 다른 출처에서 다시 알림을 보낸 경우에는 중복으로 합칠 수 있어, 실제로 연속한 두 별도 승인인지는 카드사 거래 식별자가 없는 원문만으로 완전히 판별할 수 없다. 긴 브리핑을 여러 Telegram 메시지로 보낼 때 중간 전송 뒤 실패하면 재실행이 앞 메시지를 중복 발송할 수 있다. 청크별 전송 상태를 영속화하지 않은 현재 발송 경로의 한계다.
