# 금현물 기준선(앵커+델타) — 설계

> 목적: 위탁 금현물 보유가 앱 수동 편집 후 파서에 의해 원복되는 문제를 없앤다.
> 예수금과 동일한 **기준선 + 거래 델타** 패턴으로 전환한다.

## 배경 / 문제

- 금현물 파서(`parse-notifications.mjs` 금 블록)는 매시간 **알람 탭의 금 매수 알림을 전부
  합산**해 위탁 금 행 D·E(수량g·투자금)를 **재계산·덮어쓴다**.
- 전제: "모든 금 매수가 알람에 잡힌다." 그러나 **알람 탭 도입 이전(또는 미적재) 매수분**은
  알람에 없어 파서가 모른다.
- 실제: 사용자는 22g 보유. 알람엔 2g 1건만 존재 → 파서가 22g를 **2g로 원복**. 앱에서
  수동 수정해도 다음 시간에 다시 2g로 덮어쓴다(클로버).
- 예수금에서 이미 푼 것과 동일한 구조 문제다(파서가 알람만으로 행 전체를 재계산).

## 현재 상태 (확인됨)

위탁 금 행(행7): 유형=금, 종목=`금 99.99K`, D수량=2, E투자금=431,140, C단가=210,810(수식/별도),
F현재가=218,240(GAS 라이브), H평가=436,480(=D×F 수식).
→ 파서가 D·E만 덮어쓴다(C·F·H·I는 수식/GAS, 건드리지 않음).

## 핵심 공식 (예수금과 동형)

```
금수량   = 기준수량   + Σ(그 종목 금 매수 알림 수량g, 날짜 > 기준일)
금투자금 = 기준투자금 + Σ(그 종목 금 매수 round(수량×단가), 날짜 > 기준일)
   · 기준일 이후 매수만 가산(기준일·그 이전 매수는 이미 기준값에 포함으로 간주)
   · 매수만 존재(현재 금 매도 알림 미지원 — YAGNI)
```

기준값을 어디서 얻나: 사용자가 `금기준` 표에 수동 입력(앱 편집 또는 시트 직접).
NH 출금가능금액 같은 자동 앵커가 금엔 없으므로 **항상 수동 기준 + 델타**(연금저축·IRP와 동일).

## 데이터 모델

### 신규 시트 `금기준` (예수금기준과 동형, 5열)

| 열 | 의미 | 채우는 주체 |
|----|------|------------|
| A 종목 | 금 종목명(예: 금 99.99K) | 시드(보유 금 종목) |
| B 기준수량 | 기준 시점 보유 g | 사용자(앱/시트) |
| C 기준투자금 | 기준 시점 누적 매수금 | 사용자(앱/시트) |
| D 기준일 | yyyy-MM-dd | 사용자(앱이 오늘로) |
| E 갱신시각 | 마지막 기록 시각 | 앱/파서 |

- 시트·헤더는 `ensureSheet`로 보장. 보유 금 종목(유형=금)을 시드로 추가(기준값 빈칸).
- 시드 대상 탐색: 전 계좌 탭에서 유형(E열)이 `금`인 행의 종목명.

### 표시 행 (위탁 금 행)

- 파서/앱은 **D(수량)·E(투자금)만 리터럴**로 쓴다. C(단가)·F(현재가)·H(평가)·I(수익률)는
  수식·GAS 라이브이므로 건드리지 않음(기존 금 파서와 동일).

## 동작 흐름 (파서 금 블록 교체)

1. 알람에서 금 매수 레코드 추출(기존 `parseGoldBuy`, 주문번호 dedup 유지).
2. `금기준` 표 로드 → `baseByName`(종목→{기준수량, 기준투자금, 기준일, rowNum}).
3. 종목별:
   - 기준값 **빈칸이면 skip**(표시 행 안 씀, 경고). ← 클로버 방지 핵심. 기존 "알람합 덮어쓰기" 제거.
   - 기준 있으면: `수량 = 기준수량 + Σ(qty, date>기준일)`, `투자금 = 기준투자금 + Σ(round(qty×price), date>기준일)`.
4. 표시 행 `{탭}!D{row}:E{row}` 에 `setValues`. (C·F·H 보존)
5. `--dry-run` 시 계산만 출력.

### 멱등성

매 실행 알람에서 금 매수 재수집(주문번호 dedup) + 기준 이후만 가산 → 재실행·백필 동일 결과.
기준이 항상 더해지는 앵커라 알람 누락분이 있어도 기준에 흡수돼 드리프트 없음
(연금저축·IRP 예수금과 동일하게 월/수시 수동 리셋에서 자가교정).

## 앱 변경 (금 행 수동 편집)

- **편집 대상 판별**: 보유종목 행 유형 `h.type === '금'`.
- 길게 누르면(`startLP`) 단가·수량 패널 대신 **금 전용 패널**(`editingGold` 상태):
  입력 2개 — **수량(g)**, **투자금(₩)**. 초기값: 현재 표시 행 D·E.
- 저장(`saveGold`):
  1. `금기준!A:A`에서 종목명으로 행 찾음(없으면 append 시드).
  2. `금기준!B{row}:E{row}` = `[수량, 투자금, 오늘KST, nowStr]` 로 씀(기준 리셋).
  3. 표시 행 `{acctKey}!D{sheetRow}`·`{acctKey}!E{sheetRow}` 에 즉시 반영.
  4. `sheets.fetch()`.
- 예수금 편집(`editingCash`/`saveCash`)과 동일 메커니즘. 단가·현재가·평가 수식은 안 건드림.

## 엣지 케이스

- 기준 빈칸/NaN → 표시 행 skip(경고). 앱에서 입력 전까지 현재 값 보존.
- 수량/투자금 음수·NaN 입력 → 저장 막고 안내. 0은 허용.
- 금 종목 여러 개 → 종목별 독립(현재 금 99.99K 하나).
- 금 매도 → 현재 미지원(매수만). 매도 발생 시 수동 기준 리셋으로 교정(후속 과제).

## 복구 시나리오 (사용자)

1. 배포 후 앱 위탁 탭 → 금 행 길게 누름 → 수량 `22`, 투자금 `실제 매수금액` 입력 → 저장.
2. `금기준` 표 기준수량=22·기준투자금=실액·기준일=오늘 기록 + 표시 행 22g 반영.
3. 다음 파서 실행: 기준일 이후 금 매수 알림 0건 → `22 + 0 = 22g`. 더는 원복 안 됨.
4. 이후 새 금 매수 알림(기준일 이후)만 자동 가산.

## 범위 밖 (YAGNI)

- 금 매도 처리 — 현재 적립만. 후속.
- 금 현재가/평가 자동 — 이미 gold-price.gs(GAS)가 F를 라이브 갱신.
- 금 자동 앵커(출금가능금액류) — 금엔 그런 알림 없음. 수동 기준 유지.

## 테스트 전략

- 빌드·린트 통과.
- 파서 `--dry-run`: 기준 빈칸 → skip 경고. 기준 22g/오늘 입력 후 → `22 + 0 = 22g` 출력.
- 멱등: 같은 알람 2회 → 동일 결과.
- 앱(로그인): 금 행 길게 눌러 금 패널 뜨고, 저장 후 `금기준` 갱신 + 표시 행 반영, 파서 재실행에 원복 없음.
