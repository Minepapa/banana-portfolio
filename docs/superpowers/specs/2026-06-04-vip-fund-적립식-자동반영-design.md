# VIP펀드 적립식 자동 반영 — 설계

> 목적: 연금저축 VIP한국형가치투자 펀드를 매달 수동으로 시트에 적던 작업을 없앤다.
> 삼성증권 "펀드 매수 완료 안내" 알림이 알람 탭에 쌓이면, banana 무인 잡이
> 좌수·투자금·평가금액을 재계산해 연금저축 펀드 행을 자동 갱신한다.
> (스프레드시트 직접 수정 제거 — case 1)

## 배경 / 문제

- 위탁·ISA 일반 종목은 `단가 × 수량` 체계로 매수 폼·체결 파서가 처리한다.
- VIP펀드는 매달 1일 **20만원 적립식** 매수이고, 단가/수량이 아니라 **매수금액 + 기준가** 체계라
  기존 폼에 맞지 않아 사용자가 매달 시트를 직접 열어 수동 수정해 왔다.
- 그런데 삼성증권이 매수 시 아래 알림을 보낸다(알람 탭에 적재됨):

```
[삼성증권] <펀드 매수 완료 안내>

고객님, 펀드 매수가 완료됐습니다.

- 펀드명 : VIP한국형가치투자증권자투자신탁(주식)-C-Pe
- 계좌번호 : 71612*****-15 (잔고번호:002)
- 매수금액 : 200,000원
- 매수기준가 : 2,217.41
- 매수신청일 : 2026년 6월 1일
```

→ 매수금액·매수기준가·날짜가 모두 있으므로 좌수를 역산할 수 있다. 체결/배당 파서와 같은
구조라 `parse-notifications.mjs` 확장으로 완전 무인화 가능 (앱·시트 입력 0).

## 핵심 공식

```
이번 달 좌수 = 매수금액 ÷ 매수기준가 × 1000
예) 200,000 ÷ 2,217.41 × 1000 = 90,196.5좌
```

(한국 펀드 기준가는 1,000좌당 가격 표기 관행 → ×1000)

누적 집계:
```
누적투자금  = Σ 매수금액
누적좌수    = Σ (매수금액 ÷ 매수기준가 × 1000)
평균기준가  = 누적투자금 ÷ 누적좌수 × 1000
현재 NAV    = 최신(최근 매수신청일) 매수기준가        ← 결정: 최신 매수기준가 사용
평가금액    = 누적좌수 ÷ 1000 × 현재 NAV
```

## 데이터 모델 (연금저축 펀드 행, C:I)

보유종목 행 스키마: A유형 B종목명 C단가 D수량 E투자금 F현재가 G손익 H평가금액 I수익률.
펀드 행에는 **리터럴 값**을 쓴다(라이브 수식 없음). 행은 새로 만들지 않고 **기존 행을 덮어씀**:

| 열 | 의미 | 값 |
|----|------|-----|
| C 단가 | 평균 매수기준가 | 누적투자금 ÷ 누적좌수 × 1000 (소수 2자리) |
| D 수량 | 누적좌수(천좌 단위) | 누적좌수 ÷ 1000 |
| E 투자금 | 누적 적립액 | Σ매수금액 (정수 원) |
| F 현재가 | 현재 기준가 | 최신 매수기준가 |
| G 손익 | 평가손익 | 평가금액 − 투자금 (정수 원) |
| H 평가금액 | 현재 평가 | 누적좌수 ÷ 1000 × 최신기준가 (정수 원) |
| I 수익률 | 수익률 | 평가금액 ÷ 투자금 − 1 |

**일관성**: `C×D = 누적투자금`이 정의상 정확히 성립(평균기준가·천좌 정의에서 유도). `H = D×F`도 성립.
따라서 앱의 `단가×수량 = 투자금`, `수량×현재가 = 평가금액` 표기가 깨지지 않는다.
A(유형)·B(종목명)은 기존 값 유지 — 매수기준가 표기 단위(천좌)로 단가가 작게 보이는 건 감수.

## 동작 위치 / 흐름

`scripts/parse-notifications.mjs` 확장 (launchd `com.banana.parse-notifications`, 매시간, 멱등):

1. 알람 A2:D 전수 스캔(기존). 본문에서 **펀드 매수 알림** 추가 인식.
2. 펀드 매수 레코드 추출: `{펀드명, 금액, 기준가, 날짜}`.
3. **레코드 중복 제거**: 키 `펀드명|날짜|금액|기준가`. (Kakao가 같은 알림을 두 번 적재해도 1건으로.)
4. 펀드명별 그룹 → 누적 재계산(위 공식).
5. 보유 행 매칭: 전 계좌 탭(`ISA·위탁·연금저축·IRP`) `A:B`에서 B(종목명)가
   알림 펀드명에 **포함**되는 행을 찾음(시트명 "VIP한국형가치투자" ⊂ 알림 "VIP한국형가치투자증권…").
6. 찾으면 `{탭}!C{row}:I{row}` 를 `setValues`로 덮어씀. 못 찾으면 경고 로그 후 skip(행 생성 안 함).
7. `--dry-run` 시 대상·계산만 출력.

### 정규식 (본문)

- 가드: `body.includes('펀드') && body.includes('매수기준가')`
- 펀드명: `/펀드명\s*:\s*(?<fundName>[^\n\r]+)/`
- 매수금액: `/매수금액\s*:\s*(?<amount>[\d,]+)\s*원/`
- 매수기준가: `/매수기준가\s*:\s*(?<nav>[\d,]+(?:\.\d+)?)/`
- 매수신청일: `/매수신청일\s*:\s*(?<y>\d{4})\s*년\s*(?<mo>\d{1,2})\s*월\s*(?<d>\d{1,2})\s*일/` → `yyyy-MM-dd`

## 멱등성

매 실행마다 알람 전체에서 펀드 매수 레코드를 모아 **중복 제거 후 전량 재계산**하고 행을 **덮어쓴다**.
체결내역(append)·배당금(누적 update)과 달리 펀드 행은 단일 누적 상태이므로 "재계산 후 덮어쓰기"가
가장 단순하고 멱등하다(재실행·백필해도 동일 결과, 드리프트 없음). 별도 dedup 키 저장 불필요
(단, 알람 자체 중복은 3단계 레코드 dedup으로 흡수).

## 엣지 케이스

- 매수기준가 0/NaN, 금액 0/NaN → 해당 레코드 skip.
- 매칭 보유 행 없음 → `⚠ 펀드 보유행 못 찾음: {펀드명}` 경고, skip(생성 금지 — 사용자 기존 행 존중).
- 펀드 알림 0건 → 펀드 처리 구간 자체 skip(기존 체결/배당 동작에 영향 없음).
- 여러 펀드 → 펀드명 그룹별 독립 처리.

## 전제 / 의존성 (구현 전 확인 필요)

- **삼성증권 펀드 매수 알림이 실제로 알람 탭에 적재되는가**는 Kakao-Notification 안드로이드 앱
  동작(이 레포 밖)에 달려 있다. 매수가 일어나는 매달 1일 직후 알람 탭에 본문이 들어오는지,
  또는 과거 매수분 본문을 1건 알람 탭에 넣고 `--dry-run`으로 1차 검증한다.
- 검증 안 되면 파서는 무해하게 0건 처리(기존 체결/배당 경로 영향 없음).

## 테스트 전략

- 단위: 위 알림 본문 샘플 → 파서가 `{금액 200000, 기준가 2217.41, 날짜 2026-06-01}` 추출,
  좌수 90196.5 계산 검증.
- 멱등: 같은 알림 2건(중복) 입력 → 1건만 집계되는지.
- 누적: 2개월치(서로 다른 기준가) 입력 → 누적좌수·평균기준가·평가금액 검증.
- `--dry-run`으로 실제 시트 쓰기 없이 출력 확인 → 그다음 실적재.

## 범위 밖 (YAGNI)

- 라이브 NAV(협회/네이버) 일간 조회 — v1은 최신 매수기준가로 월 1회 갱신.
- 앱 내 펀드 전용 입력 UI — 알림 자동화로 입력이 필요 없으므로 만들지 않음.
- 펀드 환매(매도) 처리 — 현재 적립만 하므로 후속 과제.
