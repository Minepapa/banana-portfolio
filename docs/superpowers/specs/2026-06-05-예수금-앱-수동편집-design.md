# 예수금 앱 수동 편집 + 현금성 라벨 — 설계

> 목적: 앱 보유종목 화면에서 **연금저축·IRP 예수금**을 직접 수정할 수 있게 한다.
> 더불어 ISA·위탁·IRP의 `현금성` 행에 채권·금처럼 네모 라벨을 달아 표기를 통일한다.
> (NH = ISA·위탁 예수금은 입금/출금 알림으로 완전 자동이므로 앱 편집 대상 아님.)

## 배경 / 문제

- `parse-notifications.mjs`가 매시간 `예수금기준` 표의 **기준액 + 거래 델타**로 각 계좌 예수금
  표시 행(E 투자금·H 평가금액)을 **재계산·덮어쓴다**.
- 따라서 앱에서 표시 행을 직접 고치면 다음 파서 실행에서 날아간다(클로버).
- 연금저축(삼성 MMF)·IRP(한국투자)는 입금 알림이 없어 사용자가 월 1회 기준을 리셋해야 하는데,
  지금은 시트를 직접 열어야만 가능. 앱에서 못 고친다.
- 또 ISA·위탁·IRP 예수금 행은 유형이 `현금성`인데 `COLORS` 맵에 `현금성` 색이 없어
  네모 라벨이 회색(`#aaa`)으로 떨어진다. 채권·금 등과 톤이 어긋난다.

## 현재 데이터 상태 (확인됨)

| 계좌 | 예수금 행 유형 | 종목명 | 소스 |
|------|------|--------|------|
| ISA | 현금성 | 예수금 | 자동(NH 앵커) |
| 위탁 | 현금성 | 예수금 | 자동(NH 앵커) |
| 연금저축 | **채권** | 삼성신종종류형 MMF 제4호 | 수동 |
| IRP | 현금성 | 예수금 | 수동 |

→ 연금저축 MMF는 유형이 `채권`이라 **이미 채권 라벨**이 붙는다(변경하지 않음).
빈 라벨은 ISA·위탁·IRP의 `현금성` 행뿐.

## A. 현금성 라벨

- `src/App.jsx` `COLORS` 맵(line ~238)에 한 줄 추가:
  ```js
  현금성: "#8A93A6",  // 슬레이트 그레이 — 위험 없는 중립 톤
  ```
- 보유종목 행 라벨 렌더(line ~3256)는 `COLORS[typeName]`를 그대로 쓰므로 코드 추가 없이
  ISA·위탁·IRP 예수금 행이 자동으로 슬레이트 네모 라벨을 얻는다.
- 연금저축 MMF(유형=채권)는 임의로 바꾸지 않는다 — 그대로 채권 라벨 유지.

## B. 연금저축·IRP 예수금 수동 편집

### 편집 대상 판별

- **현금 행 판별**: `h.name === '예수금'` 또는 `(acctKey === '연금저축' && h.name.includes('MMF'))`.
  (파서 `findCashRow` 로직과 동일하게 맞춤.)
- **편집 허용**: 위 현금 행 중 `acctKey ∈ {연금저축, IRP}`만.
- **ISA·위탁(NH)**: 현금 행이지만 편집 불가. 길게 눌러도 단가·수량 편집 패널을 열지 않고,
  `"NH 입금/출금 알림으로 자동 갱신됩니다"` 짧은 안내만(`balanceSyncMsg` 재사용).

### 편집 UI

- 현금 행을 길게 누르면(`startLP`) 기존 `editingHolding`(단가·수량) 대신 **새 상태
  `editingCash`** 를 연다. 별도 상태로 분리해 단가·수량 편집기는 손대지 않는다.
- 패널: 단일 입력 "예수금 잔액"(숫자) + 저장/취소. 단가·수량·현재가 입력 없음.
- 초기값: 현재 표시 행 평가금액(`h.eval`).

### 저장 흐름 (클로버 회피 핵심)

표시 행을 직접 고치지 않고, 파서가 읽는 **원천(`예수금기준` 표)** 을 갱신한다:

1. `예수금기준!A2:A5`에서 해당 계좌 행 번호를 종목명(A열)으로 찾음.
2. `예수금기준!B{row}:C{row}` = `[입력값, 오늘(yyyy-MM-dd)]` 로 씀(기준액·기준일 리셋).
3. **즉시 반영**: 표시 행 `{acctKey}!E{sheetRow}` 와 `{acctKey}!H{sheetRow}` 에 입력값을 써서
   앱이 바로 갱신된 잔액을 보이게 함(낙관적 업데이트).
4. `sheets.fetch()` 로 새로고침.

→ 다음 파서 실행: 기준액=입력값, 델타 = 기준일(오늘) **이후** 거래 = 당일 거래 제외 → 0 →
`기준+0=입력값` 으로 재확인. 표시 행이 날아가지 않는다.

의미: 앱에서 예수금 수정 = "지금 이 잔액이 맞다 → 여기서부터 다시 누적"하는 **기준 리셋**.
그 사이 드리프트는 다음 수동 리셋에서 교정(연금저축·IRP는 원래 월 1회 리셋 모델).

## 엣지 케이스

- 입력값 빈칸/음수/NaN → 저장 막고 안내(`balanceSyncMsg`). 0은 허용(예수금 0 가능).
- `예수금기준`에 해당 계좌 행이 없으면(이론상 없음 — 파서가 시드) → 안내 후 중단, 표시 행 안 씀.
- 표시 행 sheetRow 계산은 기존 `START_ROWS[acctKey] + h.rowOffset` 재사용.
- NH(ISA·위탁) 현금 행 길게 누름 → 편집기 안 열고 자동 관리 안내만.

## 범위 밖 (YAGNI)

- ISA·위탁 수동 편집 — NH 알림 자동이라 불필요(사용자가 B 선택).
- 연금저축 MMF 유형을 `채권`→`현금성`으로 변경 — 자산분배 영향 가능, 요청 없음. 보류.
- 예수금 전용 화면/탭 — 기존 보유종목 행 인라인 편집으로 충분.

## 테스트 전략

- 빌드·린트 통과(`npm run build`, `npm run lint`).
- 시각 검증(로그인 필요): 연금저축·IRP 예수금 행 길게 눌러 편집기 뜨는지, 저장 후
  `예수금기준` 표 기준액·기준일이 오늘로 바뀌고 표시 행이 갱신되는지.
- 파서 재실행(`node scripts/parse-notifications.mjs --dry-run`)에서 해당 계좌가
  `기준 입력값(오늘) +0 = 입력값` 으로 나오는지(클로버 없음).
- ISA·위탁 현금 행 길게 눌러 편집기 안 열리고 안내만 뜨는지.
