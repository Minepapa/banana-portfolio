# 주문함(Order Inbox) 파이프라인 — 설계

> 목적: 매수·매도·리밸런싱 신호가 "정보"로 끝나지 않고 **실행 가능한 주문서**가 되게 한다.
> 브레인스토밍(2026-07-10)으로 확인된 실패 지점: ①신호가 행동 명령이 아님 ②제약·근거가
> 안 보여 신뢰 부족 ③실행 마찰. (타이밍은 문제 아님 — 푸시는 이미 충분)

## 핵심 결정 (사용자 확정)

| 질문 | 결정 |
|------|------|
| 행동 명령의 형태 | **완성된 주문서** — 계좌·종목·방향·수량·예상금액 확정, 증권사 앱에 입력만 |
| 신뢰 조건 | **제약 검증 표시**(예수금·500만 원칙·확신 보호) + **근거 체인**(신호·평가·확신도) |
| 판단 주체 | **Node 결정론 계산 + AI 선별** — 수량·금액은 코드가, AI는 후보 중 선택·근거 산문만 |
| 생성 주기 | **주 1회(일 08:30) + 급락 O🔴 시 즉시(평일 16:50, risk-d 직후)** |
| UI | **새 "주문" 탭 + 오늘탭 요약 항목** |

## 아키텍처

```
[신호] 리밸런싱 갭(자산분배) · 급락O(리스크모니터) · 논리훼손B · 평가🟢(종목투자노트)
  → order-proposals.mjs (launchd order-weekly / order-crash)
      Node(order-candidates.mjs 순수부): 후보 선정·수량 산출·제약 체크 — 전부 결정론
      AI(weekly만, runHeadlessClaude Read전용): 후보 중 선별 + 근거 산문. qty/price 변경 금지.
      AI 실패/쿨다운 → Node 후보 그대로 적재(결정론 데이터라 안전 — 파이프라인 생존 우선)
  → 주문제안 시트 (A~N, sheet-contracts.mjs PROPOSAL_* 계약) + 텔레그램 요약 푸시
  → 앱 "주문" 탭: 대기(승인/기각/보류) → 실행 대기 → 최근 처리
  → parse-notifications.mjs: 체결 알림 ↔ 승인 주문 매칭키(계좌|종목|방향) 매칭 → 실행완료
```

## 후보 생성 규칙 (order-candidates.mjs)

- **리밸런싱**: 갭 ±5%p 자산군만. 매도 선정 = 확신 제외 → 평가 나쁜 순(🔴>🟡>무평가>🟢) →
  평가금 큰 순. 매수 = 해당 자산군 기존 최대 보유에 적립(신규 발굴은 평가 큐 소관).
  수량 = floor(|리밸금액| / 단가), 단가 = 평가금/수량(항상 KRW — 통화 혼동 차단).
- **급락O🔴**: 보유 종목만, min(500만, 예수금) 이내. 오늘 신호만(crash 모드).
- **논리훼손B🔴**: 매도평가 카드(🔴)가 있으면 전량 매도 주문. 없으면 **매도평가 자동 의뢰**
  (평가요청 시트 append — 근거 없는 매도 주문은 만들지 않는다. 평가가 정본 판단 경로).
- **평가🟢 후 미매수**: 🟢 유효 평가 후 매수 체결이 없는 종목. 미보유 KR은 잡이 yfinance로
  단가 해결, US 미보유는 v1 미지원(환율 환산 필요 — 제외+경고).

## 안전장치

- dedup: 매칭키 동일한 제안/승인 건 존재 시 재생성 skip (멱등)
- 만료: 미응답 제안 7일 후 자동 만료 (부담 없이 무시 가능)
- 보유 0건 읽기 → throw (오염 방지, readHoldings 가드와 동일 철학)
- 단가 미해결 종목은 추정하지 않고 제외+경고 (환각 차단 원칙)
- 앱 승인/기각은 K:M 한 범위 쓰기 (부분쓰기 방지), 체결 매칭은 비파괴(실패 시 그대로)
- 확신 종목: 리밸런싱 매도 후보에서 제외, 500만 초과 매수는 "확신 예외" 라벨(확정 성향 반영)
