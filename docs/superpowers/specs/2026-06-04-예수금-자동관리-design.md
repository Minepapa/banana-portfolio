# 예수금(현금) 자동 관리 — 설계

> 목적: 4개 계좌(ISA·위탁·연금저축·IRP)의 예수금을 매번 수동으로 시트에 적던 작업을 줄인다.
> NH(ISA·위탁)는 입금/출금 알림의 `출금가능금액`으로 완전 자동, 연금저축·IRP는 사용자가
> 월 1회 기준값만 입력하면 이후 매수/매도/배당이 자동 반영된다. (수동 편집 제거 — case 3)

## 배경 / 문제

- 예수금은 지금 앱이 추적하지 않는 값이라, 매수·매도·입금 때마다 사용자가 시트를 직접 고쳐 왔다.
- 알림 조사 결과 계좌가 두 부류로 갈린다:

| 계좌 | 증권사 | 입금/출금 알림 | 잔고줄(`출금가능금액`) | 가능한 방식 |
|------|--------|---------------|----------------------|-------------|
| ISA | NH | 입금안내·출금안내 | **있음** | 자동 앵커+델타 |
| 위탁 | NH | 입금안내·출금안내 | **있음** | 자동 앵커+델타 |
| 연금저축 | 삼성 | (자동이체, 알림 없음) | 없음 | 수동 기준값+델타 |
| IRP | 한국투자 | 입금완료 안내 | 없음(입금액만) | 수동 기준값+델타 |

- NH 알림 샘플(입금·출금 동일 포맷, 둘 다 잔고줄 보유):
```
[NH투자증권] 입금안내
금액 500,000원
[05/22 12:39]
계좌번호 209-02-89***2     ← ISA
NH투자 정영호
출금가능금액 : 563,371원   ← 그 시점 정답 잔고
```
```
[NH투자증권] 출금안내
...
계좌번호 205-01-59***9     ← 위탁
출금가능금액 : 1,458,563원
```

## 핵심 공식 (통일)

```
예수금(계좌) = 기준액 + Σ(그 계좌 거래, 날짜 > 기준일)
   · 매도·배당 = +,  매수·금현물 매수·펀드 적립 = −
   · 거래 → 계좌 라우팅 = 기존 종목명→탭 맵(portfolioMap) / findHoldingRow 재사용
   · 원화 예수금만 대상 — USD 체결은 외화RP(수동) 소관이라 제외
```

차이는 **기준액·기준일을 어디서 얻느냐**뿐:
- **NH(ISA·위탁)**: 파서가 입금/출금 알림 `출금가능금액` + 알림시각으로 자동 갱신 → 입금·출금마다 자동보정.
- **연금저축·IRP**: 사용자가 `예수금기준` 표에 수동 입력. 파서는 그 행의 기준액·기준일을 **읽기만** 함.

## 데이터 모델

### 신규 시트 `예수금기준` (단일 설정 표, 5열)

| 열 | 의미 | NH 행 | 연금저축·IRP 행 |
|----|------|-------|----------------|
| A 계좌 | ISA/위탁/연금저축/IRP | (고정) | (고정) |
| B 기준액 | 기준 시점 현금 | **파서가 자동 갱신** | **사용자 수동** |
| C 기준일 | 기준액의 시점(yyyy-MM-dd) | **파서가 자동 갱신** | **사용자 수동** |
| D 소스 | 자동/수동 | "자동" | "수동" |
| E 갱신시각 | 마지막 파서 계산 시각 | 파서 | 파서 |

- 시트·헤더·4개 계좌 행은 `ensureSheet` + 시드로 보장(없으면 생성).
- 파서는 NH 행만 B·C·D를 쓰고, 연금저축·IRP 행의 B·C는 **절대 건드리지 않는다**.

### 표시 행 (각 계좌 탭)

- **ISA·위탁·IRP**: 유형 `현금성`, 종목명 `예수금` 행을 사용자가 1회 만들어 둔다(없으면 파서가 경고·skip — 펀드/금과 동일하게 사용자 행 존중).
- **연금저축**: 기존 `삼성신종종류형 MMF 제4호` 행 재사용.
- 파서는 표시 행의 **E(투자금)·H(평가금액)에 계산된 예수금을 리터럴로** 쓴다(현금이므로 투자금=평가금액, 손익 0). 단가·수량·현재가 칸은 건드리지 않음.
  (앱 parseHoldings는 평가금액 H를 포트폴리오 합계에 사용 → H가 핵심.)

## 동작 흐름 (`parse-notifications.mjs` 확장)

1. 알람 전수 스캔(기존). 본문에서 **NH 입금/출금 안내** 추가 인식: `parseCashAlarm` → `{계좌번호, 잔액, tsRaw}`.
2. 계좌번호 앞자리 → 탭 매핑:

   | 앞자리 | 탭 |
   |--------|----|
   | `209-02` | ISA |
   | `205-01` | 위탁 |

   (마스킹된 가운데와 무관하게 앞자리로 구분.)
3. `예수금기준` 표 로드. NH 행(ISA·위탁): 해당 계좌 **최신** cash 알림으로 기준액·기준일 자동 갱신. 연금저축·IRP 행: 표의 사용자 입력 그대로 사용.
4. 계좌별 델타 = 기준일 **이후** 거래의 부호합:
   - 체결(execs, KRW만): 매수 −(수량×단가), 매도 +(수량×단가). 라우팅 종목명→탭.
   - 배당(divs): + 세후금액. 라우팅 종목명→탭.
   - 금현물(golds): − 수량×단가. 위탁.
   - 펀드 적립(funds): − 매수금액. 연금저축.
   - 비교 기준: 거래 날짜 > 기준일(동일자 거래는 제외 — 기준 잔고가 이미 반영했다고 간주).
5. 예수금 = 기준액 + 델타. 표시 행 E·H에 `setValues`로 덮어씀. NH 기준 행은 `예수금기준`에 갱신.
6. `--dry-run` 시 계산만 출력(쓰기 없음).

### 정규식 (NH cash 알림)

- 가드: `발신인/본문에 'NH투자증권' && ('입금안내' || '출금안내')`
- 방향: `입금안내` → 정보용(부호는 잔고가 절대값이라 불필요), `출금안내`도 동일(잔고 절대값)
- 계좌번호: `/계좌번호\s*([\d]{3}-[\d]{2}-[\d*]+)/`
- 잔액: `/출금가능금액\s*:\s*([\d,]+)\s*원/`
- 시각: 알람 A열(tsRaw) 사용. (본문 `[MM/DD HH:mm]`는 연도 없음 → A열 우선)

## 멱등성

매 실행마다 알람에서 cash 앵커를 다시 뽑고(NH 최신 1건) 거래를 전량 재합산해 예수금을 **재계산·덮어씀**.
증분(running −/+)이 아니라 "기준액 + 기준 이후 거래합"이라 재실행·백필해도 동일 결과. NH는 새 입금/출금
알림이 올 때마다 기준이 갱신돼 수수료·세금·환전 등 미포착 흐름 드리프트가 **자동 보정**된다.
연금저축·IRP는 사용자가 월 1회 기준 리셋 → 그 사이 드리프트만 누적되고 리셋에서 교정.

## 엣지 케이스

- `예수금기준`에 연금저축·IRP 기준액 미입력(빈칸) → 해당 계좌 skip(표시 행 안 씀, 경고).
- 표시 행(예수금/MMF) 없음 → 경고 후 skip(행 생성 안 함, 사용자 행 존중).
- NH cash 알림 0건 → NH 기준 갱신 skip(기존 기준 유지). 기존 기준도 없으면 skip.
- USD 체결 → KRW 예수금 델타에서 제외(외화RP는 수동).
- 종목명이 여러 탭 중복(dupNames) → portfolioMap에서 제외되어 계좌 미상 → 델타 누락 가능(기존 체결내역과 동일 한계). 다음 NH 앵커/수동 리셋에서 보정.

## 전제 / 의존성

- 알람 탭이 마지막 앵커/기준일 이후 거래를 모두 담고 있어야 정확(오래된 알람이 퇴출되면 그 이전 거래는 이미 앵커에 반영돼 무관).
- NH 입금/출금 알림이 실제로 알람 탭에 적재돼야 NH 자동 동작(Kakao 앱 소관). 미적재 시 무해하게 기존 기준 유지.

## 테스트 전략

- 단위: NH cash 알림 → `parseCashAlarm`이 `{계좌번호 209-02-89***2, 잔액 563371}` 추출, 앞자리→ISA 매핑.
- 델타: 기준일 이후 매수 1·매도 1·배당 1 → 부호합 검증.
- 멱등: 같은 입력 2회 → 동일 예수금.
- 수동계좌: 기준액 입력 + 기준일 이후 펀드적립 → 예수금 = 기준액 − 적립.
- `--dry-run`으로 실제 쓰기 없이 출력 확인 → 그다음 실적재.

## 범위 밖 (YAGNI)

- 외화(외화RP) 예수금 자동 — USD 입금/환전 알림 포맷 미확인, 현행 수동 유지.
- IRP 디폴트옵션 TDF 자동매수 차감 — 자동매수 알림 유무 미확인. 알림 오면 매수로 잡혀 자동 반영, 아니면 수동 리셋에서 교정.
- 예수금 전용 입력 UI — `예수금기준` 표 직접 입력으로 충분.
