# banana-portfolio v2 — 구현 계획서

> 이 문서는 `docs/ARCHITECTURE-V2.md`(설계 정본)의 실행 순서를 정리한 것이다. 설계
> 내용 자체는 재정의하지 않는다 — "무엇을 만들지"는 이미 확정됐고, 여기서는 "어떤
> 순서로, 무엇을 재사용해서, 어떤 스킬로" 만들지만 다룬다.
>
> **아직 구현 시작 아님** — `CLAUDE.md`의 "이제 구현해보자" 해제 조건 전까지는 이
> 계획서 자체도 설계 문서 작성의 일부다.

## 순서를 정하는 원칙

1. **위험한 것(실제 돈이 걸린 것)을 최대한 뒤로 미룬다** — 특히 KIS 실제 주문 실행
   API는 섀도우모드가 이미 있으므로 "로그만 남기는 경로"로 대부분의 개발·검증이
   가능하다. 실제 체결 API는 섀도우모드로 충분히 검증된 뒤, 실전전환 직전에 만든다.
2. **모두가 의존하는 기반부터** — Vault 구조·공용 락 유틸이 없으면 그 위의 어떤 것도
   못 만든다.
3. **v1 자산을 최대한 재사용** — 새로 짜는 게 아니라 "이식"인 부분을 각 단계에 명시한다.
4. **각 단계마다 완료 기준(Definition of Done)을 둔다** — "설계에 다 있으니 만들면
   끝"이 아니라, 뭘 확인해야 다음 단계로 넘어가도 되는지 명시한다.

> 가장 흔한 구현버그(첨도 컨벤션: scipy/pandas 기본값인 초과첨도 vs 이 공식이 요구하는
> 비초과첨도)를 사전에 특정. (2) 백테스트 생존편향 문제 — 지수구성종목 과거 이력 API가
> Phase 9와 같은 KRX 로그인 벽에 막혀 있는지 조사한 결과, **무료로 해결 가능**함을 확인:
> `FinanceDataReader`의 `KRX-DELISTING`(상장폐지종목 목록, 1960~현재 4,172건, 한진해운
> 등 실제 사례로 검증 완료)을 현재상장목록과 합치면 로그인 없이 특정 과거 시점 유니버스
> 재구성 가능(한국 개인퀀트 커뮤니티의 표준 우회법으로도 확인) — 공식 지수 자체(버퍼룰
> 등)가 아니라 "시가총액 상위 근사"라는 기존에 받아들인 트레이드오프는 별개로 남음.
>
> - `scripts/lib/stats.mjs`(17 테스트): `mean`·`sampleVariance`·`skewness`·`kurtosis`
>   (⚠️ 의도적으로 비초과 컨벤션 — 적률비 m4/m2²로 직접 계산해 정규분포에서 자연히 3이
>   나옴)·`standardNormalCdf`(A&S 7.1.26 erf 근사)·`standardNormalInvCdf`(Acklam 알고리즘,
>   분위함수)·`sharpeRatio`(연율화)·`maxDrawdown`·`annualizedReturn`.
> - `scripts/lib/deflated-sharpe.mjs`(11 테스트): `computeSR0`(N=trialSharpeRatios 배열
>   길이 그대로 — "몇 개 시도했다"를 배열과 분리해서 못 주장하게)·`computeDeflatedSharpeRatio`
>   (논문 Eq.2, 반환값은 Sharpe가 아니라 확률). 논문 Appendix A.3(상관된 시도의 실효
>   독립시도수 보정)은 원문에서 글리프 단위 검증 실패해 구현 안 함 — 기본 케이스(독립
>   시도 가정)만, 이 생략의 방향성(관대해지는 쪽 아니라 오히려 더 엄격해지는 쪽 — 안전)을
>   직접 수치 검증까지 마침.
> - `scripts/lib/walk-forward.mjs`(7 테스트): `splitWalkForwardWindows`(5년/1년 롤링,
>   불완전한 마지막 윈도우는 버림).
>
> 독립 코드리뷰 — 원 논문과 다른 방식(Simpson 적분+Newton법)으로 핵심 수치를 재계산해
> 대조, 6개 구현버그 클래스(첨도 컨벤션·자유도·왜도 부호·SR0분산 대상 혼동·N 과소집계·
> 주기 불일치) 전부 정상 처리 확인. MEDIUM 4건 발견해 수정: ①연율화 SR과 기간당
> sampleSize를 섞으면 DSR이 조용히 낙관적으로 틀어지는 계약 위험(주석 강화+통합테스트로
> 고정) ②Appendix A.3 생략의 안전방향 주석이 실제로는 반대로 적혀 있었음(SR0가 N에
> 단조증가함을 직접 재검증해 correct: 명목N>실효N이면 게이트가 관대해지는게 아니라
> 더 엄격해지는 쪽) ③왜도≠0·첨도≠3 정확값 회귀테스트 부재(범위체크만으론 계수오류를
> 못 잡음 — 손계산값으로 고정) ④N-정직성·주기일관성은 순수함수 자체로 강제 불가 —
> Phase 10 실제 배선 시 호출측에서 반드시 강제할 것으로 명시. LOW 1건(walk-forward.mjs
> Date 인스턴스 앨리어싱)도 수정. 테스트 856개 통과, lint 클린.
>
> **아직 아무 것도 실제 데이터에 연결 안 됨** — 지금은 순수 수학만. 다음: 역사적 유니버스
> 재구성(KRX-DELISTING+현재상장 결합) → 역사적 OCF 대규모 수집(OpenDart) → 워크포워드
> 엔진 결합 → N(시도횟수) 정직 집계 방법론 확정(OCF/P 단일·MSCI 3지표조합·OCF/P+PEAD
> 3가지 비교가 이미 N≥3을 암시) → 실제 백테스트 1회 완주.

## Phase 11 — 브로커 실주문 API (KIS 매수/매도)

> ⚠️ **실제 자금이 처음 걸리는 지점.** 지금 `scripts/lib/kis.mjs`는 시세·잔고조회
> 전용이고 "자동매매는 이 모듈의 범위 밖"이라고 코드 주석에 명시돼 있다 — 주문 실행은
> 완전히 새로 만드는 부분이다.

**작업**:
- KIS 주문 API 연동(매수/매도), 지정가 우선 원칙 반영

  유지)
- 레이트리밋 처리(v1 자산 승계 — HTTP 500으로도 오는 레이트리밋을 놓쳤던 v1의 근본
  버그가 이미 수정된 이력 있음, 그 교훈 재적용)

**완료 기준**: 섀도우모드에서 Phase 8·9가 **둘 다** 최소 1개월 이상 안정적으로
운영됐고, Phase 10 백테스트 게이트를 통과한 뒤에만 이 Phase 착수. 소액 실거래로
3~6개월 병행 검증 계획(설계서에 이미 명시)과 맞물림.

**추천 스킬**:

  전부 재점검

  훅으로 막아두는 것을 권장
- **`tdd`** + **`/code-review`**(엄격 적용)
