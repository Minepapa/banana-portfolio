# 카카오 알림 중계를 구글시트에서 Firestore로 교체 (ADR 0005 대체)

ADR 0005는 Kakao-Notification 안드로이드 앱을 건드리지 않기 위해 구글시트를 "폰→Mac
임시 우편함"으로 유지하기로 했었다. 2026-08-22 v2 전수 감사 중 오너가 "카카오 알림도
Vault로 바로 쌓이게 할 수 없냐"고 물어 재검토했고, 실제로 안드로이드 리포(별도,
`~/Stockproject/Kakao-Notification`)에 접근 가능해 수정 비용을 다시 계산한 결과 더는
그 전제가 유효하지 않았다.

**검토했던 대안과 기각 사유**:
- **텔레그램으로 직접 전송** — 처음엔 공사량이 가장 적어 보였으나, 실측(Telegram Bot
  API 공식 문서)해보니 봇은 자기가 보낸 메시지를 자기 getUpdates로 못 받는다(봇↔봇
  가시성도 기본 차단, "Bot-to-Bot Communication Mode"라는 예외가 있지만 관리자 권한+
  프라이버시모드+양쪽 설정이 다 필요한 까다로운 기능). 결국 안드로이드가 "진짜 사용자
  계정"으로 로그인해야 하는데(MTProto) 이건 미니 텔레그램 클라이언트를 새로 만드는
  수준이라 기각. 이미 살아있는 승인용 봇(Zeus) 채널을 이런 실험으로 건드리는 리스크도
  부담이었다.
- **Drive 동기화 폴더에 파일로 직접 쓰기** — Vault 자체가 이미 Google Drive로 동기화되고
  있어 개념적으로 가장 자연스러웠으나, "로컬 파일만 쓰면 기존 FolderSync/Autosync가
  Drive로 올려준다"는 전제가 실측 검증되지 않았다(폰에서 직접 확인 필요) — 불확실성이
  남아 후순위로 미룸.
- **Firestore 직접 쓰기(채택)** — 이 프로젝트가 이미 Firebase 콘솔·보안규칙·Admin
  SDK·서비스계정까지 전부 갖춘 상태였다(Phase 6, 대시보드 미러용). 프로토콜 단의 함정이
  없고, Mac 쪽은 기존 `sync-firestore-mirror.mjs`와 완전히 같은 인증 패턴을 재사용할 수
  있어 실측 불확실성이 가장 적었다.

**결정**: Kakao-Notification 앱이 구글시트 API 대신 Firestore `kakaoInbox` 컬렉션에
알림 원문을 직접 쓴다(안드로이드 쪽 인증은 기존 대시보드와 같은 Google Sign-In→Firebase
Auth 재사용). `parse-notifications-to-vault.mjs`는 그 컬렉션을 Admin SDK로 읽어 기존
파서(`notification-parsers.mjs`)에 그대로 넣는다 — 파서는 원문(시각·본문) 두 필드만
보므로 소스 전환에 영향받지 않는다.

**구글시트와 다른 점 하나**: 시트는 처리된 행을 안 지워도 비용이 없었지만(ADR 0005가
"정리는 구현 시 결정"으로 미뤄둔 채 실제로 한 번도 안 지움), Firestore는 읽기가 문서
수만큼 과금된다. 그래서 이번엔 처리 직후 문서를 삭제한다(`kakao-inbox.mjs`) — Vault
Facts/Ledger의 파일명 dedup은 안전망으로 그대로 남겨, 삭제 타이밍이 어긋나도 이중기록은
안 생긴다.

**여파**:
- 안드로이드 앱은 별도 리포에서 Firebase 프로젝트에 새로 등록돼야 한다(`google-services.json`
  발급 — Firebase 콘솔 조작 필요, 이 리포만으로는 못 끝남).
- ADR 0005가 미해결로 남겨뒀던 위험("Mac이 잠든 사이 시트 회전삭제로 알림 유실")은 이
  전환으로 사실상 해소된다 — Firestore 컬렉션은 시트처럼 앱이 자체 회전시키지 않고,
  Mac이 늦게 깨어나도 문서가 그대로 남아있다.
- ADR 0005 자체는 삭제하지 않고 "대체됨" 표시만 남긴다(이 리포의 관례 — 결정 이력은
  지우지 않고 정정 주석으로 남긴다).
