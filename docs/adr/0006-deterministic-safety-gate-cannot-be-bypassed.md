# 결정론적 검문소는 어떤 승인으로도 우회할 수 없다

critic 리뷰(TIER 1)가 "안전장치 계층이 통째로 비어있다"고 지적했다 — Athena·Themis·Zeus의
LLM 판단과 Frank의 텔레그램 승인만으로 실제 주문이 나가는 구조였고, 주문한도·중복방지·
가격이탈 같은 기계적 안전판이 전혀 없었다.

그래서 지금 프로젝트에 이미 있던 철학("Node가 결정론적으로 계산·집행, LLM은 해석·판단만")
을 주문 실행에도 적용해, Frank가 "승인"이라고 답장해도 **브로커 API 호출 직전에 LLM
판단과 무관한 결정론적 검문소(가격이탈·보유정합성·중복방지·제안-승인 일치성·시장개장상태·
단일활성제안)를 반드시 통과**해야 실제 체결이 나가도록 확정했다. 어떤 부서·오너 승인도
이 검문소를 우회하지 못한다.

의도적으로 두지 않은 것도 있다: "하루 거래 건수 상한"은 버그로 인한 난사 주문을 막는
서킷브레이커로 검토했으나, 500만원 분할매수·장기보유 원칙상 거래 빈도 자체가 원래 낮아
불필요하다고 판단해 채택하지 않았다 — 이건 누락이 아니라 명시적 결정이다.

**여파**: 실제 구현 시 이 검문소는 Athena·Themis·Zeus의 판단 경로와 완전히 독립된 코드
경로(Node 스크립트)로 만들어야 하며, 나중에 "이 검문소 때문에 정상 거래가 막혔다"고
급하게 우회 경로를 추가하고 싶어질 수 있다 — 그 유혹 자체가 이 ADR이 막으려는 것이다.
