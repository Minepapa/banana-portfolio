# Kairos 호출 전 Node 기계적 필터를 두는 2단 구조

사용 흐름을 처음부터 끝까지 다시 훑어보다가, 투자실행협의체가 장시작/매시정각/종가
폴링마다 보유종목 전체에 대해 Hermes→Kairos→Athena→Themis LLM 체인을 통째로 돌리면
quota 부담이 커질 수 있다는 게 드러났다. 판단 원칙("수치 산출은 기계적이어도 되지만
결론은 LLM 종합")을 신호 생성 단계에도 적용하지 않으면, 아무 신호도 없는 평범한 폴링
주기에도 매번 여러 부서의 LLM을 깨우게 된다.

그래서 Kairos 앞에 **Node가 이동평균·RSI 같은 지표를 기계적으로 계산하는 1단계**를
두고, 그 값이 의미있는 구간(임계치)에 들어올 때만 **Kairos(LLM)가 호출돼 해석하는
2단계**로 넘어가는 구조를 확정했다. 이평선·RSI 계산 자체는 사실상 비용이 없고, 정말
판단이 필요한 순간에만 LLM을 쓴다.

**고려했던 대안**: 매 폴링마다 Kairos를 항상 호출 — 구현은 단순하지만 대부분의 폴링
주기에서 "특별한 신호 없음"이라는 결론을 내기 위해서만 LLM을 쓰게 돼 비효율적이라 기각.

**여파**: 실제 구현 시 "의미있는 구간"의 구체적 임계치(예: RSI 30/70, 이평선 이격도 등)
는 추세추종 알고리즘 세부 설계(가장 마지막 순서로 미뤄둔 백로그) 단계에서 정해야 한다 —
이 ADR은 필터가 있다는 아키텍처 결정만 기록하고, 임계치 자체는 별도.
