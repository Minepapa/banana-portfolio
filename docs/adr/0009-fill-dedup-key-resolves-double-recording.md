# 체결 기록 이중화는 새 조정 메커니즘 없이 기존 dedup 키로 해결

브로커 API 실행경로(KIS 자동체결)와 카카오 알림 파싱경로가 같은 체결을 각자 Vault
Facts/Ledger에 기록하려 드는 문제가 critic 리뷰에서 지적됐다. 어느 경로가 권위 있는
기록인지, 조정을 위한 새 메커니즘이 필요한지 검토가 필요했다.

이미 설계된 **멱등 dedup 키**(날짜|구분|종목명|수량, v1에서 이식)가 이 문제를 새 메커니즘
없이 그대로 해결한다는 결론을 내렸다. 두 경로 중 어느 쪽이든 먼저 그 키로 Ledger에 쓰면,
뒤이어 같은 키로 도착하는 다른 경로는 "이미 기록됨"으로 인식해 새 항목을 만들지 않는다.
KIS 이관 계좌는 브로커 API 응답을 1차 기록으로 삼고 뒤따르는 카카오 알림은 대조 확인용
(불일치 시 Hermes가 경고), 미이관 계좌(NH·삼성)는 카카오 알림이 지금처럼 유일한 소스로
남는다.

**고려했던 대안**: 체결 기록용 새 조정/합의 계층(예: 두 경로의 기록을 별도 큐에 모아
사후 병합하는 절차) — 이미 있는 멱등 설계로 충분해 불필요한 복잡도로 판단, 기각.

**여파**: 부분체결(승인 100주, 체결 30주)처럼 두 경로의 값 자체가 다른 경우의 State
재계산 절차는 이 결정만으로는 해소되지 않는다 — 별도 세부 설계가 필요(TIER 2 잔여 항목).
