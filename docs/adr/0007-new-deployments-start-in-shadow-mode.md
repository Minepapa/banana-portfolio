# 신규 자동체결 배포는 항상 섀도우모드로 시작

critic 리뷰가 지적한 대로, 실거래를 자동으로 움직이는 시스템을 검증 없이 바로 실전
투입하는 건 무모하다. 하지만 오너는 "얼마나 오래 검증해야 실전 전환할지"에 대해 기간을
강제하는 대신 스스로 판단하고 싶어했다.

그래서 KIS 자동체결 경로는 **처음 배포 시 항상 섀도우모드로 시작**하기로 확정했다.
섀도우모드에서는 파이프라인 전체(가격폴링→신호생성→투자실행협의체→Zeus 승인→텔레그램
제안·Frank 승인/거부)가 실전과 동일하게 돌지만, 마지막 브로커 API 호출만 실제 발주 대신
로그로 대체된다. 실전 전환은 **최소 기간 강제 없이**, Frank가 텔레그램에 명시적 명령어
("실전전환")를 보내야만 이뤄진다 — 자동 전환은 없다.

**고려했던 대안**: 최소 2주 같은 강제 기간 — 오너가 "기간 제한 없이 자율 판단"을 선택해
기각. 성급한 전환 자체를 구조적으로 막지는 않지만, 최소한 기본값은 항상 안전한 쪽(섀도우)
에서 시작하게 만들어 "깜빡하고 처음부터 실전으로 배포"하는 실수를 방지한다.

**여파**: 실전 전환 여부를 나타내는 상태 플래그가 필요하고, Proposal의 "섀도우체결" 상태는
Facts/Ledger의 실제 체결 기록과 명확히 구분돼야 한다(가짜 체결이 진짜 장부에 섞이면 안 됨).
